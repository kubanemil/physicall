# Plan: E0.3 Hello Triangle

## Overview

This plan implements the "Hello Triangle" milestone (E0.3) for the Physicall project. Building on the existing WebGPU initialization (E0.2), we add a render pipeline and vertex buffer to display a colored triangle on the canvas. This is the first visual rendering beyond a solid color clear.

The triangle will have RGB colors at each vertex (red, green, blue) that interpolate across the surface, demonstrating the full vertex-to-fragment data flow.

## Architecture Decisions

- **Shader loading**: Use `include_str!()` for compile-time embedding (best for WASM, no runtime file loading)
- **Shader location**: `shaders/triangle.wgsl` at project root (flat structure for M0, reorganize in M1)
- **Vertex format**: Position `[f32; 3]` + Color `[f32; 3]` = 24 bytes per vertex
- **Pipeline layout**: `None` (auto-layout) since no bind groups needed yet
- **Primitive topology**: `TriangleList` with counter-clockwise winding, back-face culling

## Prerequisites

- [ ] E0.2 complete (WebGPU initialization working, canvas shows solid color)

## Phase 1: Shader & Dependencies

### Goal

### Files to Create

- `shaders/triangle.wgsl` - Vertex and fragment shader for colored triangle

### Files to Modify

- `Cargo.toml` (workspace root) - Add `bytemuck` to workspace dependencies
- `crates/physicall-core/Cargo.toml` - Add `bytemuck` dependency

### Shader Design

**`shaders/triangle.wgsl`**

Structs:
- `VertexInput` - `@location(0) position: vec3f`, `@location(1) color: vec3f`
- `VertexOutput` - `@builtin(position) clip_position: vec4f`, `@location(0) color: vec3f`

Entry points:
- `@vertex fn vs_main(input: VertexInput) -> VertexOutput` - Pass position to clip space, forward color
- `@fragment fn fs_main(input: VertexOutput) -> @location(0) vec4f` - Output interpolated color with alpha 1.0

### Dependency Addition

**Workspace `Cargo.toml`**:
```toml
bytemuck = { version = "1.21", features = ["derive"] }
```

**Crate `Cargo.toml`**:
```toml
bytemuck = { workspace = true }
```

## Phase 2: Pipeline & Rendering

### Goal

Add the `Vertex` struct, render pipeline, and vertex buffer to `lib.rs`. Modify the render pass to draw the triangle.

### Files to Modify

- `crates/physicall-core/src/lib.rs` - Add Vertex, pipeline, buffer, draw calls

### Module Design

**`Vertex` struct** (add near top of file)

```rust
#[repr(C)]
#[derive(Copy, Clone, Debug, bytemuck::Pod, bytemuck::Zeroable)]
struct Vertex {
    position: [f32; 3],
    color: [f32; 3],
}
```

Methods:
- `Vertex::desc() -> wgpu::VertexBufferLayout<'static>` - Returns layout with 2 attributes

**`VERTICES` constant** - 3 vertices forming a triangle:
- Top center (0.0, 0.5, 0.0) - Red
- Bottom left (-0.5, -0.5, 0.0) - Green
- Bottom right (0.5, -0.5, 0.0) - Blue

**`State` struct** - Add two new fields:
- `render_pipeline: wgpu::RenderPipeline`
- `vertex_buffer: wgpu::Buffer`

**`State::new()`** - After surface configuration, add:
1. Load shader via `device.create_shader_module()` with `include_str!("../../../shaders/triangle.wgsl")`
2. Create render pipeline via `device.create_render_pipeline()` with:
   - Vertex state: shader module, "vs_main" entry, `Vertex::desc()` buffer layout
   - Fragment state: shader module, "fs_main" entry, surface format target
   - Primitive state: TriangleList, Ccw front face, Back cull mode
3. Create vertex buffer via `device.create_buffer_init()` with VERTICES data

**`State::render()`** - Inside render pass block, add after creating `render_pass`:
1. `render_pass.set_pipeline(&self.render_pipeline)`
2. `render_pass.set_vertex_buffer(0, self.vertex_buffer.slice(..))`
3. `render_pass.draw(0..3, 0..1)` - Draw 3 vertices, 1 instance

### Integration

Data flow:
```
VERTICES constant (Rust)
    ↓ bytemuck::cast_slice
vertex_buffer (GPU)
    ↓ set_vertex_buffer(0, ...)
Vertex shader reads @location(0), @location(1)
    ↓ vs_main transforms to clip space
Fragment shader receives interpolated color
    ↓ fs_main outputs RGBA
Surface texture displays triangle
```
