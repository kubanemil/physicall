# Plan: E1.2 Primitive Rendering

## Overview

Add rendering support for three fundamental primitives: points, lines, and spheres. This establishes the visual building blocks needed for physics simulation visualization in subsequent milestones.

The implementation adds a depth buffer for proper 3D rendering, creates separate render pipelines for each primitive type, and provides a unified API for managing primitive data. Points use instanced quads (WebGPU has no native point size), lines use `LineList` topology, and spheres use an icosphere mesh with instancing.

## Architecture Decisions

- **Points as instanced quads**: WebGPU lacks `@builtin(point_size)`, so render 2-triangle quads with fragment discard for circular appearance
- **Axis-aligned quads**: Simpler than billboarding, acceptable for learning project
- **Custom icosphere generation**: Implement ourselves for learning rather than using crate
- **Subdivision level 2**: 162 vertices per sphere - good visual quality without excess geometry
- **Uniform color per primitive type**: Per-instance colors deferred to M2 (compute buffers)
- **Single render pass**: All pipelines share camera bind group, switch pipelines within one pass
- **Keep lib.rs monolithic for now**: Modularization deferred to avoid scope creep

### New Shader: `shaders/point.wgsl`

```wgsl
struct CameraUniform { view_proj: mat4x4<f32> };
@group(0) @binding(0) var<uniform> camera: CameraUniform;

struct QuadInput {
    @location(0) quad_pos: vec2f,
}

struct InstanceInput {
    @location(2) world_pos: vec3f,
    @location(3) size: f32,
    @location(4) color: vec3f,
}

struct VertexOutput {
    @builtin(position) clip_position: vec4f,
    @location(0) uv: vec2f,
    @location(1) color: vec3f,
}

@vertex
fn vs_main(quad: QuadInput, instance: InstanceInput) -> VertexOutput {
    // Axis-aligned quad: expand in world XY plane
    let world_pos = vec3f(
        instance.world_pos.x + quad.quad_pos.x * instance.size,
        instance.world_pos.y + quad.quad_pos.y * instance.size,
        instance.world_pos.z,
    );
    var out: VertexOutput;
    out.clip_position = camera.view_proj * vec4f(world_pos, 1.0);
    out.uv = quad.quad_pos * 0.5 + 0.5;  // Convert to 0..1
    out.color = instance.color;
    return out;
}

@fragment
fn fs_main(in: VertexOutput) -> @location(0) vec4f {
    let dist = length(in.uv - vec2f(0.5));
    if (dist > 0.5) { discard; }
    return vec4f(in.color, 1.0);
}
```

### Integration

Pipeline vertex buffers (two buffers):
```rust

```

Draw call with instancing:
```rust

render_pass.set_index_buffer(self.quad_index_buffer.slice(..), wgpu::IndexFormat::Uint16);
render_pass.draw_indexed(0..6, 0, 0..self.point_instance_count);
```

## Phase 4: Sphere Rendering

### Goal

Add sphere primitives using icosphere mesh (level 2 = 162 vertices) with instancing.

### Files to Modify

- `crates/physicall-core/src/lib.rs` - Add icosphere generation, sphere pipeline, instance buffer
- `shaders/sphere.wgsl` - New shader for instanced spheres with basic lighting

### Module Design

**New struct: `SphereVertex`**

```rust
#[repr(C)]
#[derive(Copy, Clone, Debug, bytemuck::Pod, bytemuck::Zeroable)]
struct SphereVertex {
    position: [f32; 3],
    normal: [f32; 3],  // For lighting, equals position on unit sphere
}
```

**New struct: `SphereInstance`**

```rust
#[repr(C)]
#[derive(Copy, Clone, Debug, bytemuck::Pod, bytemuck::Zeroable)]
struct SphereInstance {
    position: [f32; 3],
    radius: f32,
    color: [f32; 3],
    _padding: f32,
}
```

**Icosphere generation function:**

```rust
fn generate_icosphere(subdivisions: u32) -> (Vec<SphereVertex>, Vec<u32>) {
    // 1. Create base icosahedron (12 vertices, 20 triangles)
    // 2. For each subdivision:
    //    - For each triangle, split into 4 by adding edge midpoints
    //    - Normalize midpoints to unit sphere
    //    - Use edge cache (BTreeMap<(u32,u32), u32>) to avoid duplicates
    // 3. Return vertices and indices
}
```

Algorithm constants:
- Golden ratio: `t = (1.0 + 5.0_f32.sqrt()) / 2.0`
- Base icosahedron: 12 vertices from 3 orthogonal rectangles
- Level 2: 162 vertices, 320 triangles, 960 indices

sphere_instance_count: u32,
```

**Demo data:**

```

### New Shader: `shaders/sphere.wgsl`

```wgsl
struct CameraUniform { view_proj: mat4x4<f32> };
@group(0) @binding(0) var<uniform> camera: CameraUniform;

struct VertexInput {
    @location(0) position: vec3f,
    @location(1) normal: vec3f,
}

struct InstanceInput {
    @location(2) world_pos: vec3f,
    @location(3) radius: f32,
    @location(4) color: vec3f,
}

struct VertexOutput {
    @builtin(position) clip_position: vec4f,
    @location(0) world_normal: vec3f,
    @location(1) color: vec3f,
}

@vertex
fn vs_main(vertex: VertexInput, instance: InstanceInput) -> VertexOutput {
    let world_pos = instance.world_pos + vertex.position * instance.radius;
    var out: VertexOutput;
    out.clip_position = camera.view_proj * vec4f(world_pos, 1.0);
    out.world_normal = vertex.normal;  // Normal unchanged for uniform scale
    out.color = instance.color;
    return out;
}

@fragment
fn fs_main(in: VertexOutput) -> @location(0) vec4f {
    // Simple directional light from camera direction
    let light_dir = normalize(vec3f(0.3, 0.5, 1.0));
    let diffuse = max(dot(normalize(in.world_normal), light_dir), 0.2);
    return vec4f(in.color * diffuse, 1.0);
}
```

### Integration

Same pattern as points - two vertex buffers (geometry + instances), indexed draw with instance count.
