# Plan: E2.2 Particle Simulation

## Overview

Implement gravity-driven particle simulation with floor collision and UI controls. This replaces the current N-body gravitational attraction with constant downward gravity, adds floor boundary collision with bounce damping, and exposes gravity strength to a user-adjustable slider.

The implementation modifies existing compute shader and Rust code rather than creating new infrastructure. The GPU compute pipeline from E2.1 remains intact; only the physics logic changes.

## Architecture Decisions

- **Gravity model**: Constant downward force (not N-body) - simpler, O(n) instead of O(n²), matches user expectation of "falling"
- **Floor position**: y = -2.0 (allows particles to fall from spawn position ~2-4 units above)
- **Bounce damping**: 0.7 (loses 30% energy per bounce - visually satisfying, settles eventually)
- **Default gravity**: 10.0 (Earth-like feel at simulation scale)
- **Gravity range**: -20.0 to +20.0 (allows reverse gravity for experimentation)
- **Integration method**: Keep semi-implicit Euler (already implemented, stable enough)
- **SimParams extension**: Add floor_y and bounce_damping fields (32-byte aligned)

- [x] E2.1 GPU Compute Pipeline working (confirmed in research)

## Phase 1: Physics Core

### Goal

Particles fall under constant gravity and bounce off floor. Visually verifiable without any UI changes.

### Files to Modify

- `shaders/particle_compute.wgsl` - Replace N-body with constant gravity + floor collision
- `crates/physicall-core/src/lib.rs` - Extend SimParams, update constants, modify initial spawn

### Shader Changes (`particle_compute.wgsl`)

**SimParams struct** - Add floor_y and bounce_damping:

```wgsl
struct SimParams {
    delta_time: f32,
    gravity_strength: f32,
    damping: f32,
    particle_count: u32,
    floor_y: f32,
    bounce_damping: f32,
    _padding1: f32,
    _padding2: f32,
}
```

**Main function** - Replace N-body loop with:
1. Constant gravity: `acceleration = vec3f(0.0, -params.gravity_strength, 0.0)`
2. Semi-implicit Euler integration (keep existing)
3. Floor collision check after position update:
   - If `position.y < floor_y`: set `position.y = floor_y`, reflect and damp velocity.y

### Rust Changes (`lib.rs`)

**SimParams struct** (~line 431):
```rust
struct SimParams {
    delta_time: f32,
    gravity_strength: f32,
    damping: f32,
    particle_count: u32,
    floor_y: f32,
    bounce_damping: f32,
    _padding: [f32; 2],
}
```

**Constants** (~line 441):
- Change `GRAVITY_STRENGTH` from 0.00005 to 10.0
- Add `FLOOR_Y: f32 = -2.0`
- Add `BOUNCE_DAMPING: f32 = 0.7`

**Initial particle spawn** (`create_initial_particles`, ~line 447):
- Change base_radius from 3.0 to 1.5
- Add vertical offset: spawn center at y = 2.0 (so particles are above floor)
- Remove tangential velocity (start at rest for cleaner falling demo)

**Render function** (~line 1291):
- Include new fields when creating SimParams

### Integration

- SimParams buffer size increases from 16 to 32 bytes (already aligned)
- Compute bind group layout unchanged (same binding, just larger buffer)
- No changes to render pipeline

## Phase 2: JS Integration

### Files to Modify

- `crates/physicall-core/src/lib.rs` - Add mutable gravity state and WASM export
- `web/src/main.ts` - Import new function (no UI yet)

### Rust Changes (`lib.rs`)

**State struct** - Add mutable gravity field:
```rust
struct State {
    // ... existing fields ...
    gravity_strength: f32,  // NEW: mutable gravity
}
```

**State::new()** - Initialize gravity_strength to DEFAULT_GRAVITY (10.0)

**State::render()** - Use `self.gravity_strength` instead of constant when building SimParams

**New WASM export**:
```rust
#[wasm_bindgen]
pub fn set_gravity(strength: f32) {
    STATE.with(|s| {
        if let Some(state) = s.borrow_mut().as_mut() {
            state.gravity_strength = strength.clamp(-20.0, 20.0);
        }
    });
}
```

### TypeScript Changes (`main.ts`)

**Import** - Add `set_gravity` to import statement:
```typescript
import init, { init_webgpu, render, resize, reset_camera, set_gravity }
    from '../../crates/physicall-core/pkg/physicall_core';
```

No other changes yet - UI comes in Phase 3.

### Integration

- `set_gravity()` updates State.gravity_strength
- Next render() call picks up new value via SimParams
- Clamped to [-20, 20] to prevent extreme values

### TypeScript Changes (`main.ts`)

**After WebGPU init**, add slider event handler:
```typescript
const gravitySlider = document.getElementById('gravity-slider') as HTMLInputElement;
```
