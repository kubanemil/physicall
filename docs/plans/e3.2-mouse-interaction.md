# Plan: E3.2 Mouse Interaction

## Overview

This plan implements mouse-based particle interaction for the Physicall simulation. Users will be able to click and drag particles to move them (imparting velocity on release), hover over particles to see visual feedback, and middle-click to delete particles. The existing click-to-spawn functionality is preserved for clicks on empty space.

The implementation uses a CPU-side position copy for picking (simplest approach for 2,000 particles), force-based dragging via compute shader modifications, and shader-based visual highlighting for hover/drag feedback.

## Architecture Decisions

- **CPU-side position tracking**: Maintain `Vec<[f32; 3]>` synced after spawn/delete operations. 64KB overhead is negligible, avoids GPU readback complexity.
- **Force-based dragging**: Apply strong spring force toward cursor position in compute shader. Particle retains momentum on release for physical feel.
- **Swap-with-last deletion**: O(1) delete by moving last particle to deleted slot. Particle ordering doesn't matter for N-body simulation.
- **Shader-based highlighting**: Pass hovered/dragged particle index to shader via uniform. Highlighted particle renders brighter.
- **Click target detection**: On mousedown, pick particle first. If hit → drag mode. If miss → camera orbit or spawn.
- **Position-based drag when paused**: When simulation is paused, directly set particle position (no physics running).

## Phase 2: Drag State & Compute Shader Integration

### Goal

Enable dragging a picked particle by applying force toward cursor in compute shader.

### Files to Modify

- `crates/physicall-core/src/lib.rs` - Extend InputState, State, add drag handling
- `shaders/particle_compute.wgsl` - Add drag force calculation

### Module Design

**InputState additions**:

```rust
struct InputState {
    // ... existing fields ...

    dragging_particle_idx: Option<u32>,  // Currently dragged particle
    drag_world_pos: Option<Vec3>,        // Current drag target in world space
}
```

**SimParams additions** (must match WGSL):

```rust
#[repr(C)]
struct SimParams {
    delta_time: f32,
    gravitational_constant: f32,
    damping: f32,
    particle_count: u32,
    softening_sq: f32,
    drag_strength: f32,           // NEW: force multiplier for drag
    drag_target: [f32; 3],        // NEW: world position to drag toward
    dragged_particle_idx: i32,    // NEW: -1 if none, else particle index
}
```

**WGSL SimParams** (shaders/particle_compute.wgsl):

```wgsl
struct SimParams {
    delta_time: f32,
    gravitational_constant: f32,
    damping: f32,
    particle_count: u32,
    softening_sq: f32,
    drag_strength: f32,
    drag_target: vec3f,
    dragged_particle_idx: i32,
}
```

**Compute shader drag logic** (added to main function):

```wgsl
// After N-body acceleration calculation, before integration:
if (i32(idx) == params.dragged_particle_idx) {
    let to_target = params.drag_target - particle.position;
    acceleration = to_target * params.drag_strength;
    // Optionally dampen velocity for smoother control
    particle.velocity *= 0.8;
}
```

**Constants**:

```rust
const DRAG_STRENGTH: f32 = 50.0;  // Tunable - higher = snappier response
```

### Integration

**Mousedown flow**:
1. Call `pick_particle(screen_x, screen_y)`
2. If Some(idx) → set `dragging_particle_idx = Some(idx)`, don't accumulate camera rotation
3. If None → existing behavior (camera orbit on drag, spawn on click)

**Mousemove flow**:
1. If `dragging_particle_idx.is_some()` → update `drag_world_pos` via ray-plane intersection
2. Else → existing camera rotation accumulation

**Mouseup flow**:
1. Clear `dragging_particle_idx` and `drag_world_pos`

**Render loop**:
1. If dragging, set `SimParams.dragged_particle_idx` and `drag_target`
2. Else set `dragged_particle_idx = -1`

**Paused behavior**:
- When paused and dragging, directly update `particle_positions[idx]` and write to GPU buffer
- Skip compute pass (already skipped when paused)

## Phase 3: Visual Feedback (Hover & Drag Highlight)

### Goal

Provide visual feedback when hovering over or dragging a particle.

### Files to Modify

- `crates/physicall-core/src/lib.rs` - Track hovered particle, pass to shader
- `shaders/point.wgsl` - Highlight hovered/dragged particle

### Module Design

**InputState additions**:

```rust
struct InputState {
    // ... existing fields ...

    current_mouse_pos: Option<(f32, f32)>,  // For hover detection
}
```

**State additions**:

```rust
struct State {
    // ... existing fields ...

    hovered_particle_idx: Option<u32>,
}
```

**New uniform for render shader** - Add to existing camera bind group or create new:

Option A (simpler): Pack into existing `SimParams` and share with render shader
Option B: Create `RenderParams` uniform for render-specific data

**Recommended**: Option A - reuse SimParams, add `hovered_particle_idx: i32`

**WGSL point shader changes**:

```wgsl
// Add to uniforms (if using SimParams)
@group(0) @binding(1) var<uniform> sim_params: SimParams;

// In fragment shader, modify color:
if (instance_idx == sim_params.hovered_particle_idx ||
    instance_idx == sim_params.dragged_particle_idx) {
    color = mix(color, vec3f(1.0, 1.0, 1.0), 0.5);  // Brighten
}
```

**Challenge**: Instance index not available in fragment shader by default.

**Solution**: Pass instance index from vertex to fragment shader:

```wgsl
struct VertexOutput {
    // ... existing ...
    @location(2) instance_idx: u32,
}
```

### Integration

**Mousemove** (when not dragging):
1. Update `current_mouse_pos`
2. Call `pick_particle()` to find hovered particle
3. Store in `hovered_particle_idx`

**Performance note**: Picking on every mousemove with 2,000 particles is ~2,000 ray-sphere tests. At ~10ns each = 20μs. Acceptable.

## Phase 4: Delete Functionality

### Goal

Allow users to delete particles via middle-click.

### Files to Modify

- `crates/physicall-core/src/lib.rs` - Add delete method, handle middle-click

### Module Design

**New method**: `delete_particle`

```rust
impl State {
    fn delete_particle(&mut self, idx: u32)
    // Swaps particle at idx with last particle, decrements count
    // Updates both GPU buffers and CPU position tracking
}
```

**InputState additions**:

```rust
struct InputState {
    // ... existing fields ...

    pending_delete: Option<(f32, f32)>,  // Screen coords for middle-click
}
```

**Mouse event handling**:
- Middle button (button == 1) → on mouseup, set `pending_delete`

### Integration

**Delete flow**:
1. On middle-click, call `pick_particle()`
2. If Some(idx) → call `delete_particle(idx)`
3. If None → ignore

**Swap-with-last implementation**:
1. If `idx == active_particle_count - 1` → just decrement count
2. Else:
   - Read last particle from `particle_positions`
   - Write last particle to slot `idx` in both GPU buffers
   - Update `particle_positions[idx] = particle_positions.pop()`
3. Decrement `active_particle_count`

**Edge case**: Don't allow deleting below 0 particles (already handled by check).

## Rollback Plan

If issues arise:
1. Revert lib.rs and shader changes via git
2. Core functionality (camera, spawn, render) is not modified, only extended

## Open Questions

- **Pick radius tuning**: May need adjustment based on user testing. Start with `PARTICLE_SIZE * 2.0`.
- **Drag strength tuning**: May feel too snappy or too floaty. Start with `50.0`, adjust based on feel.
- **Hover performance**: If picking on every mousemove causes issues with larger particle counts, consider throttling to every 2-3 frames.
