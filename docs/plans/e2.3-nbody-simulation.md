# Plan: E2.3 N-Body Simulation

## Overview

This plan implements N-body gravitational simulation where particles attract each other, plus click-to-spawn interaction. The compute shader will be modified to calculate O(n²) gravitational forces between all particle pairs. Users can click on the canvas to spawn new particles that immediately participate in the simulation.

## Architecture Decisions

- **Uniform mass**: All particles have equal mass (no changes to Particle struct). Simplifies implementation; size visually implies mass.
- **Repurpose SimParams**: Replace `gravity_strength` with `gravitational_constant` (G), use padding slots for `softening_sq`.
- **Disable floor collision**: N-body simulation runs in free space for cleaner gravitational dynamics.
- **Reduced particle count**: Default to 200 particles (vs 10,000) due to O(n²) complexity. Max capacity 2,000.
- **Pre-allocated buffers**: Buffers sized for MAX_PARTICLES; track `active_particle_count` separately.
- **Movement threshold for click**: If mouse moves < 5px between mousedown/mouseup, treat as click (spawn). Otherwise, drag (camera orbit).
- **Spawn plane**: New particles spawn on the plane passing through `camera.target` with normal pointing toward camera.

## Phase 1: N-Body Compute Shader

### Goal

Replace constant downward gravity with particle-to-particle gravitational attraction.

### Files to Modify

- `shaders/particle_compute.wgsl` - Replace physics logic with N-body force calculation
- `crates/physicall-core/src/lib.rs` - Update SimParams struct and constants

### Changes

**`shaders/particle_compute.wgsl`** - Complete rewrite of physics logic:

```wgsl
// SimParams changes:
struct SimParams {
    delta_time: f32,
    gravitational_constant: f32,  // G (was gravity_strength)
    damping: f32,
    particle_count: u32,
    softening_sq: f32,            // epsilon² (was floor_y)
    // unused padding slots
}

// Main function changes:
// - Remove floor collision logic
// - Add O(n²) force accumulation loop:
//   for each other particle:
//     diff = other.position - particle.position
//     dist_sq = dot(diff, diff) + softening_sq
//     force_mag = G / dist_sq
//     acceleration += normalize(diff) * force_mag
// - Keep semi-implicit Euler integration
```

**`crates/physicall-core/src/lib.rs`** - Update Rust side:

1. Rename `SimParams` fields:
   - `gravity_strength` → `gravitational_constant`
   - `floor_y` → `softening_sq`
   - Remove `bounce_damping` (unused)

2. Update constants:
   ```rust
   const PARTICLE_COUNT: u32 = 200;        // Reduced for N-body
   const MAX_PARTICLES: u32 = 2_000;       // Pre-allocated capacity
   const PARTICLE_SIZE: f32 = 0.03;        // Larger for fewer particles
   const GRAVITATIONAL_CONSTANT: f32 = 1.0; // Tunable G
   const SOFTENING_SQ: f32 = 0.01;         // Prevents singularity
   const DAMPING: f32 = 1.0;               // No damping for orbits
   ```

3. Update `SimParams` struct to match shader.

4. Update `State::render()` to use new constants.

### Changes

**`crates/physicall-core/src/lib.rs`** - Multiple additions:

4. **Add State fields for dynamic particles**:
   ```rust

       // existing fields...
       active_particle_count: u32,  // Tracks how many particles are active
       max_particles: u32,          // Buffer capacity

   ```

5. **Add spawn method to State**:
   ```rust
   impl State {
       fn spawn_particle(&mut self, world_pos: Vec3) {
           if self.active_particle_count >= self.max_particles { return; }

           let particle = Particle {
               position: world_pos.to_array(),
               size: PARTICLE_SIZE,
               velocity: [0.0, 0.0, 0.0],
               _padding: 0.0,
           };

           // Write to both buffers at active_particle_count offset
           let offset = self.active_particle_count as u64 * size_of::<Particle>();
           self.queue.write_buffer(&self.particle_buffers[0], offset, bytemuck::bytes_of(&particle));
           self.queue.write_buffer(&self.particle_buffers[1], offset, bytemuck::bytes_of(&particle));

           self.active_particle_count += 1;
       }
   }
   ```

6. **Modify render() to check for pending spawns**:

               ray_origin, ray_dir, self.camera.target, plane_normal

## Open Questions

- **Particle count for performance**: 200 is conservative. May be able to increase to 500+ depending on GPU. Tune after Phase 1.
- **Orbital stability**: Semi-implicit Euler may cause orbit decay. If noticeable, consider velocity Verlet in future iteration.
- **Spawn velocity**: Currently zero. Could add small random velocity or velocity toward center for more interesting dynamics (deferred to M3).
