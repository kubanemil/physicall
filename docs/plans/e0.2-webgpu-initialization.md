# Plan: E0.2 WebGPU Initialization

## Overview

This plan implements WebGPU initialization for Physicall, enabling the browser to render a solid color canvas using wgpu compiled to WASM. It covers three user stories: rendering a colored canvas (E0.2.1), displaying error messages for unsupported browsers (E0.2.2), and handling canvas resize (E0.2.3).

The implementation creates the `web/` frontend directory, integrates wgpu into the Rust crate, and establishes the JavaScript-driven render loop pattern that will be used throughout the project.

## Architecture Decisions

- **Animation loop**: JavaScript-driven via `requestAnimationFrame` calling exported `render()` function
- **Canvas sizing**: Full viewport (100vw x 100vh) with ResizeObserver for responsive resize
- **State management**: Thread-local `RefCell<Option<State>>` for storing wgpu resources
- **WebGPU detection**: TypeScript checks `navigator.gpu` before loading WASM
- **Error handling**: Rust panics converted to console errors; TS displays user-friendly messages
- **Build flag**: `RUSTFLAGS=--cfg=web_sys_unstable_apis` required for WebGPU APIs

## Prerequisites

- [x] E0.1 completed (WASM builds and console_log works)
- [ ] Chrome 113+ or compatible browser for testing

**`crates/physicall-core/src/lib.rs`**

```rust
// Types and signatures only

/// Holds all wgpu resources needed for rendering
struct State {
    surface: wgpu::Surface<'static>,
    device: wgpu::Device,
    queue: wgpu::Queue,
    config: wgpu::SurfaceConfiguration,
    size: (u32, u32),
}

impl State {
    /// Async constructor - creates wgpu instance, adapter, device, surface
    async fn new(canvas: web_sys::HtmlCanvasElement) -> Self;

    /// Reconfigure surface with new dimensions
    fn resize(&mut self, width: u32, height: u32);

    /// Render a single frame (solid color clear)
    fn render(&mut self) -> Result<(), wgpu::SurfaceError>;
}

// Thread-local storage for State
thread_local! {
    static STATE: RefCell<Option<State>> = RefCell::new(None);
}

/// Called from JS to initialize WebGPU with given canvas ID
#[wasm_bindgen]
pub async fn init_webgpu(canvas_id: &str) -> Result<(), JsValue>;

/// Called from JS each frame via requestAnimationFrame
#[wasm_bindgen]
pub fn render() -> Result<(), JsValue>;

/// Called from JS when canvas resizes
#[wasm_bindgen]
pub fn resize(width: u32, height: u32);
```

Key implementation details:
- Use `wgpu::Backends::BROWSER_WEBGPU` for instance
- Surface created via `SurfaceTarget::Canvas(canvas)`
- Clear color: `wgpu::Color { r: 0.1, g: 0.2, b: 0.3, a: 1.0 }` (dark blue-gray)
- Handle `SurfaceError::Lost/Outdated` by reconfiguring

### Integration

TypeScript calls:
1. `init_webgpu("canvas")` on startup (awaited)
2. `render()` every frame via requestAnimationFrame
3. `resize(w, h)` when ResizeObserver fires

### Files to Modify

### Module Design

**`web/src/main.ts`** - Detection logic

```typescript
interface WebGPUCheckResult {
  supported: boolean;
  error?: string;
}

async function checkWebGPUSupport(): Promise<WebGPUCheckResult>;
function getErrorMessage(): string;  // Browser-specific messages
function showError(message: string): void;  // Display in #error div

async function main() {
  const check = await checkWebGPUSupport();
  if (!check.supported) {
    showError(check.error ?? getErrorMessage());
    return;
  }
  // ... proceed with WASM init
}
```

**Error message logic:**
- Check `window.isSecureContext` first (HTTPS/localhost required)
- Check `navigator.gpu` exists
- Try `navigator.gpu.requestAdapter()` to verify GPU available
- Browser-specific messages for Chrome, Firefox, Safari

    resize(pendingWidth, pendingHeight);
