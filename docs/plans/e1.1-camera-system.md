# Plan: E1.1 Camera System

## Overview

Implement an interactive orbit camera for the Physicall WebGPU simulation. Users will be able to orbit the camera by dragging the mouse, zoom with scroll wheel, and reset to default view. This transforms the current fixed-perspective triangle into a 3D scene that can be explored from any angle.

## Architecture Decisions

- **Linear algebra**: Use `glam` (not cgmath/nalgebra) - wgpu standard, native WebGPU depth range, bytemuck support
- **Camera model**: Spherical coordinates (radius, azimuth, polar) with look-at matrix
- **Input handling**: web-sys closures with `Rc<RefCell<InputState>>` for shared state
- **State management**: Input state separate from render State (closures need Rc, State uses thread_local)
- **Module organization**: Keep in lib.rs initially, extract to camera.rs/input.rs if it gets large
- **Default camera**: radius=3.0, azimuth=PI/4, polar=PI/6, target=origin, fov=45°

## Prerequisites

- [x] M0 complete (WebGPU initialization, triangle rendering works)

### Module Design

**`OrbitCamera`** - Camera position via spherical coordinates

Fields:
- `target: Vec3` - Point to orbit around
- `radius: f32` - Distance from target (zoom)
- `azimuth: f32` - Horizontal angle (radians)
- `polar: f32` - Vertical angle (radians, clamped ±89°)
- `min_radius: f32`, `max_radius: f32` - Zoom limits

Methods:
- `new(target: Vec3, radius: f32) -> Self`
- `eye(&self) -> Vec3` - Calculate camera position from spherical coords
- `view_matrix(&self) -> Mat4` - look_at_rh(eye, target, Y)
- `rotate_azimuth(&mut self, delta: f32)`
- `rotate_polar(&mut self, delta: f32)` - Clamps to avoid gimbal lock
- `zoom(&mut self, delta: f32)` - Clamps to min/max radius
- `reset(&mut self)` - Return to default position

**`Projection`** - Perspective projection (changes on resize only)

Fields:
- `aspect: f32`, `fov_y: f32`, `z_near: f32`, `z_far: f32`

Methods:
- `new(width: u32, height: u32) -> Self` - fov=45°, near=0.1, far=100.0
- `resize(&mut self, width: u32, height: u32)`
- `matrix(&self) -> Mat4` - perspective_rh()

**`CameraUniform`** - GPU-compatible uniform data

```rust
#[repr(C)]
#[derive(Copy, Clone, Pod, Zeroable)]
struct CameraUniform {
    view_proj: [[f32; 4]; 4],
}
```

Methods:
- `new() -> Self` - Identity matrix
- `update(&mut self, camera: &OrbitCamera, projection: &Projection)`

## Phase 2: GPU Integration

### Goal

Integrate camera with rendering pipeline. Triangle should render from new camera perspective.

### Files to Modify

- `crates/physicall-core/src/lib.rs` - Update State struct and pipeline
- `shaders/triangle.wgsl` - Add camera uniform, transform vertices

### State Struct Changes

Add fields to `State`:
```rust
camera: OrbitCamera,
projection: Projection,
camera_uniform: CameraUniform,
camera_buffer: wgpu::Buffer,
camera_bind_group_layout: wgpu::BindGroupLayout,
camera_bind_group: wgpu::BindGroup,
```

### State::new() Changes

After device/queue creation, before pipeline:

1. Create OrbitCamera with defaults
2. Create Projection from canvas dimensions
3. Create CameraUniform and initialize with camera/projection
4. Create camera_buffer (UNIFORM | COPY_DST)
5. Create camera_bind_group_layout (binding 0, VERTEX visibility)
6. Create camera_bind_group

Then modify pipeline creation:
1. Create pipeline layout with `&[&camera_bind_group_layout]`
2. Pass `layout: Some(&pipeline_layout)` to render_pipeline

### State::resize() Changes

Add: `self.projection.resize(width, height)`

### State::render() Changes

Before render_pass.draw():
1. Update camera_uniform from camera/projection
2. queue.write_buffer camera data
3. render_pass.set_bind_group(0, &camera_bind_group, &[])

### Shader Changes

Add at top of `triangle.wgsl`:
```wgsl
struct CameraUniform {
    view_proj: mat4x4<f32>,
};

@group(0) @binding(0)
var<uniform> camera: CameraUniform;
```

Change vs_main:
```wgsl
output.clip_position = camera.view_proj * vec4f(input.position, 1.0);
```

## Phase 3: Mouse Input

### Goal

Implement drag-to-orbit and scroll-to-zoom. Camera responds to mouse input.

### Files to Modify

- `crates/physicall-core/src/lib.rs` - Add InputState, event setup, update logic

### Module Design

**`InputState`** - Tracks mouse state between events

```rust
struct InputState {
    is_dragging: bool,
    last_x: i32,
    last_y: i32,
    rotate_delta: (f32, f32),
    zoom_delta: f32,
}
```

Methods:
- `new() -> Self`
- `take_deltas(&mut self) -> ((f32, f32), f32)` - Returns and clears accumulated deltas

**Global input state:**
```rust
thread_local! {
    static INPUT_STATE: Rc<RefCell<InputState>> = Rc::new(RefCell::new(InputState::new()));
}
```

### Event Setup Functions

**`setup_mouse_events(canvas: &HtmlCanvasElement, state: Rc<RefCell<InputState>>) -> Result<(), JsValue>`**

Registers three listeners:
1. `mousedown` on canvas - If button==0, set is_dragging=true, store position
2. `mousemove` on canvas - If dragging, accumulate delta, update last position
3. `mouseup` on window - Set is_dragging=false (window to catch outside releases)

**`setup_wheel_event(canvas: &HtmlCanvasElement, state: Rc<RefCell<InputState>>) -> Result<(), JsValue>`**

Registers wheel listener with `passive: false`:
1. Call prevent_default()
2. Normalize delta_y by delta_mode
3. Accumulate to zoom_delta

### Integration

**In `init_webgpu()`:**
1. Get Rc clone of INPUT_STATE
2. Call setup_mouse_events(canvas, state.clone())
3. Call setup_wheel_event(canvas, state)

**New method `State::update_camera(&mut self, rotate: (f32, f32), zoom: f32)`:**
- Apply rotation: `camera.rotate_azimuth(-rotate.0 * ROTATE_SPEED)`
- Apply rotation: `camera.rotate_polar(-rotate.1 * ROTATE_SPEED)`
- Apply zoom: `camera.zoom(zoom * ZOOM_SPEED)`

Constants: `ROTATE_SPEED = 0.005`, `ZOOM_SPEED = 0.5`

**In `render()` function:**
1. Take deltas from INPUT_STATE
2. Call state.update_camera(rotate, zoom)
3. (Rest of render unchanged - camera_uniform update already happens)

## Phase 4: Camera Reset

### Goal

Allow user to reset camera to default position via exported function.

### Files to Modify

- `crates/physicall-core/src/lib.rs` - Add reset_camera export
- `web/src/main.ts` - Add keyboard listener for reset

### Rust Changes

**Add to OrbitCamera:**
```rust
const DEFAULT_RADIUS: f32 = 3.0;
const DEFAULT_AZIMUTH: f32 = std::f32::consts::FRAC_PI_4; // 45°
const DEFAULT_POLAR: f32 = std::f32::consts::FRAC_PI_6;   // 30°

pub fn reset(&mut self) {
    self.radius = DEFAULT_RADIUS;
    self.azimuth = DEFAULT_AZIMUTH;
    self.polar = DEFAULT_POLAR;
    self.target = Vec3::ZERO;
}
```

**New export:**
```rust
#[wasm_bindgen]
pub fn reset_camera() {
    STATE.with(|s| {
        if let Some(state) = s.borrow_mut().as_mut() {
            state.camera.reset();
        }
    });
}
```

### TypeScript Changes

**In main.ts, after init_webgpu():**
```typescript
import { reset_camera } from '../../crates/physicall-core/pkg/physicall_core';

document.addEventListener('keydown', (e) => {
    if (e.key === 'r' || e.key === 'R') {
        reset_camera();
    }
});
```

## Rollback Plan

All changes are additive. To rollback:
1. Revert shader to remove camera uniform
2. Revert pipeline to `layout: None`
3. Remove camera fields from State
4. Remove input event setup
5. Remove glam dependency

Or simply: `git checkout main -- crates/ shaders/ web/`

## Open Questions

1. **Sensitivity tuning**: ROTATE_SPEED and ZOOM_SPEED values may need adjustment after testing
2. **Camera for M3**: When particle interaction is added, may need modifier key (Shift) to distinguish camera drag from particle drag
3. **Touch support**: Not in scope for E1.1, but similar pattern would work for touch events
