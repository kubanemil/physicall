# Plan: E4.1 - Collision Detection

## Overview

Add particle-particle collision detection with impulse-based response and GPU-accelerated spatial hashing to the Physicall simulation. Currently, particles pass through each other — they only interact via N-body gravitational attraction. After this implementation, particles will bounce off each other and off a floor boundary, and a spatial hash will enable efficient O(n) neighbor lookups for collision at scale (1000+ particles).

The implementation is split into two functional phases: (1) brute-force collision + floor bounce added to the existing compute shader, validating the physics, then (2) spatial hash infrastructure on the GPU replacing brute-force collision with hash-based neighbor queries.

## Architecture Decisions

- **Brute-force first, then optimize**: Phase 1 adds collision inside the existing O(n²) N-body loop (zero new dispatches). Phase 2 adds spatial hashing. This isolates collision physics from hash complexity.
- **Collision in same pass as N-body**: The N-body loop already iterates all particles. In Phase 1, collision piggybacks on this loop. In Phase 2, collision uses the spatial hash but stays in the same shader.
- **Impulse-based elastic collision**: Equal-mass particles. Impulse formula: `j = -(1+e) * v_n / 2` where `e` is restitution (0.8) and `v_n` is approaching speed along collision normal. Each thread independently computes its own particle's impulse — no race conditions with ping-pong pattern.
- **Positional correction**: Each thread pushes its particle away by half the overlap distance. Both threads in a collision pair independently correct, achieving full separation.
- **Floor collision added**: The PRFAQ expects particles to "pile up on the floor." No floor exists currently, so we add a floor at y = -2.0 with bounce response.
- **Fixed-bucket spatial hash**: Avoids prefix sum complexity. Each hash cell stores up to `MAX_PER_CELL = 16` particle indices. Uses `atomicAdd` for insertion. 4096 cells × 16 entries = 256 KB.
- **Shared pipeline layout**: All compute pipelines (hash_clear, hash_insert, physics) share a 2-bind-group layout `[compute_group, hash_group]` to minimize Rust boilerplate. Hash-only shaders simply ignore unused group(0) bindings.
- **Separate compute passes**: One pass per dispatch (clear → insert → physics) with implicit wgpu barriers between passes ensuring correct ordering.
- **N-body stays O(n²)**: The spatial hash optimizes collision only. N-body optimization is out of scope.
- **SimParams expanded to 64 bytes**: Replace existing `_padding` with `restitution`, add `floor_y`, `cell_size`, `num_cells`, and new padding to reach 64-byte alignment.

## Phase 1: Brute-Force Collision + Floor Bounce

### Goal

Particles visibly collide with each other and bounce off a floor boundary. Validates collision physics before adding spatial hash optimization.

### Files to Modify

- `shaders/particle_compute.wgsl` — Add collision detection/response in N-body loop + floor bounce after integration
- `crates/physicall-core/src/lib.rs` — Expand SimParams, add collision constants, update sim_params population

### Design

**New constants** in `lib.rs` (after existing physics constants ~line 642):

- `RESTITUTION: f32 = 0.8` — Slightly inelastic collisions
- `FLOOR_Y: f32 = -2.0` — Floor boundary y-coordinate

**SimParams expansion** (Rust struct at line 620, WGSL struct at line 11):

Replace the existing `_padding` field with `restitution: f32`, then append: `floor_y: f32`, `cell_size: f32`, `num_cells: u32`, `_padding: f32`. New total: 64 bytes (16-byte aligned). Set `cell_size` and `num_cells` to 0 in Phase 1 (unused).

**Collision logic** in `particle_compute.wgsl` — inside the existing N-body `for` loop (after line 55), add:

For each pair, compute actual distance (without softening). If `actual_dist < particle.size + other.size` and `actual_dist > epsilon`:
1. Compute collision normal = `diff / actual_dist`
2. Accumulate position correction: push away by `overlap * 0.5` along normal
3. Compute relative velocity along normal. If approaching (`v_n > 0`): accumulate velocity impulse `-(1+restitution) * v_n * 0.5` along normal

After the loop, apply accumulated collision velocity delta to `particle.velocity` before integration. Apply accumulated position correction to `particle.position` after integration.

**Floor bounce** in `particle_compute.wgsl` — after position integration (after line 69):

If `particle.position.y - particle.size < params.floor_y`: clamp position to `floor_y + particle.size`, reflect y-velocity with restitution damping.

**Rust changes** in `lib.rs`:
- Update `SimParams` struct definition (line 620-633)
- Update sim_params construction in `render()` (line 1724-1735) to include restitution and floor_y
- Update `reset_simulation()` if it touches sim_params

### Integration

- SimParams layout change affects both `particle_compute.wgsl` and `point.wgsl` (which also declares SimParams for hover highlighting). Update both WGSL structs identically.
- No TypeScript changes — collision is purely GPU-side.
- Existing features (gravity, drag, spawn, delete, pause, reset) are unaffected — collision is additive.

## Phase 2: GPU Spatial Hash

### Goal

Replace brute-force collision (which piggybacks on O(n²) N-body) with hash-based O(n) neighbor queries. Add 3 new compute dispatches per frame: clear → insert → physics. Collision portion scales to 1000+ particles.

### Files to Create

- `shaders/hash_clear.wgsl` — Compute shader to zero out cell counters
- `shaders/hash_insert.wgsl` — Compute shader to assign particles to hash cells

### Files to Modify

- `shaders/particle_compute.wgsl` — Add group(1) hash bindings, replace brute-force collision loop with hash-based neighbor query (N-body loop unchanged)
- `crates/physicall-core/src/lib.rs` — New buffers, bind group layout, pipelines, dispatch logic

### Design

**Constants**:

- `NUM_CELLS: u32 = 4096` — Hash table size (power of 2)
- `MAX_PER_CELL: u32 = 16` — Max particles per cell bucket
- `CELL_SIZE: f32 = 2.0 * PARTICLE_SIZE` — Grid cell size (0.06)

**New GPU Buffers** in `lib.rs`:

1. `cell_count_buffer`: `NUM_CELLS * 4` bytes — `array<atomic<u32>>`, usage: `STORAGE | COPY_DST`
2. `cell_entries_buffer`: `NUM_CELLS * MAX_PER_CELL * 4` bytes — `array<u32>`, usage: `STORAGE`

**Hash Bind Group** (group 1):

Layout entries:
- Binding 0: `cell_count` — storage buffer (read_write for clear/insert, read for physics)
- Binding 1: `cell_entries` — storage buffer (read_write for insert, read for physics)

Single bind group instance (no ping-pong needed — rebuilt every frame).

**Pipeline Layout**:

New shared layout: `[compute_bind_group_layout, hash_bind_group_layout]`

Three new compute pipelines using this layout:
1. `hash_clear_pipeline` — entry point from `hash_clear.wgsl`
2. `hash_insert_pipeline` — entry point from `hash_insert.wgsl`
3. Replace existing `compute_pipeline` with updated pipeline that includes group(1) bindings

**Shader: `hash_clear.wgsl`**:

Single `@compute @workgroup_size(256) fn main()` that zeros `cell_count[idx]` for each cell index. Declares group(0) bindings matching `compute_bind_group_layout` (unused) and group(1) bindings for hash data.

**Shader: `hash_insert.wgsl`**:

Single `@compute @workgroup_size(256) fn main()` that:
1. Reads particle position from `particles_in[idx]`
2. Computes 3D cell coordinates: `floor(pos / cell_size)`
3. Hashes cell coords: `(cx * 73856093 + cy * 19349663 + cz * 83492791) % num_cells`
4. `atomicAdd(&cell_count[hash], 1)` to get insertion offset
5. If offset < `MAX_PER_CELL`: writes particle index to `cell_entries[hash * MAX_PER_CELL + offset]`

Uses group(0) binding 0 (particles_in) and binding 2 (sim_params), plus group(1) bindings.

**Shader: `particle_compute.wgsl` modifications**:

Add group(1) bindings for `cell_count` (read) and `cell_entries` (read).

Replace brute-force collision accumulation (added in Phase 1) with hash-based neighbor query:
- Compute own cell hash
- Iterate over own cell + 26 neighbors (3×3×3 grid)
- For each neighbor cell, iterate over `cell_count[neighbor_hash]` entries (capped at MAX_PER_CELL)
- Read particle index from `cell_entries[neighbor_hash * MAX_PER_CELL + j]`
- Check distance + apply collision (same impulse logic as Phase 1)

The N-body gravitational loop remains unchanged (still O(n²), still iterates all particles).

**Dispatch flow** in `lib.rs` `render()` (replacing current single compute pass at line 1766-1776):

```
if !self.paused {
    // Pass 1: Clear spatial hash
    { compute_pass → hash_clear_pipeline, dispatch ceil(NUM_CELLS / 256) }

    // Pass 2: Insert particles into hash
    { compute_pass → hash_insert_pipeline, dispatch ceil(particle_count / 256) }

    // Pass 3: N-body + hash collision + integration
    { compute_pass → physics_pipeline, dispatch ceil(particle_count / 256) }
}
```

Each pass is a separate `encoder.begin_compute_pass()` block for implicit barriers.

**Bind group construction** — existing ping-pong `compute_bind_groups[2]` are reused at group(0). A single `hash_bind_group` is bound at group(1) for all three passes.

**State struct additions**:
- `cell_count_buffer: wgpu::Buffer`
- `cell_entries_buffer: wgpu::Buffer`
- `hash_bind_group: wgpu::BindGroup`
- `hash_clear_pipeline: wgpu::ComputePipeline`
- `hash_insert_pipeline: wgpu::ComputePipeline`
- Existing `compute_pipeline` is recreated with the new 2-group layout

**SimParams update**: Set `cell_size = CELL_SIZE` and `num_cells = NUM_CELLS` (were 0 in Phase 1).

### Integration

- The physics pipeline bind group at group(0) is the same existing ping-pong bind group — rendering continues to work unchanged.
- `reset_simulation()` does not need to clear hash buffers (rebuilt every frame).
- Spawn/delete operations don't touch hash buffers.

## Rollback Plan

Each phase is independently verifiable. If Phase 2 (spatial hash) causes issues, revert to Phase 1 (brute-force collision) which is fully functional for smaller particle counts. The brute-force approach piggybacks on the existing O(n²) N-body loop, adding no extra dispatches.
