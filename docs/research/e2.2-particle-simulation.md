# Research: E2.2 Particle Simulation

## Research Question

What is the current state of the codebase and what needs to be built for E2.2 (Particle Simulation) - specifically:
1. Particles falling under gravity
2. Particles bouncing off floor boundary
3. Adjustable gravity strength from UI

## Summary

**Key Finding: The foundation for E2.2 is already largely implemented.** The codebase contains a fully functional GPU compute pipeline (E2.1) with N-body gravitational simulation running on 10,000 particles at 60fps. The existing implementation uses semi-implicit Euler integration, double-buffered particle storage, and velocity-based rendering.

**What exists:**
- Complete compute shader pipeline with ping-pong buffers
- Particle struct with position, velocity, size
- SimParams uniform with delta_time, gravity_strength, damping
- N-body mutual gravitational attraction (particles attract each other)
- Semi-implicit Euler integration
- Delta time clamping (max 1/30 second)
- Instanced rendering of 10,000 particles
- Orbit camera with mouse controls

**What needs to be modified for E2.2:**
1. **Change gravity model**: Current implementation is N-body (mutual attraction). E2.2 needs a constant downward gravity force instead.
2. **Add floor collision**: No boundary collision exists currently - particles can move freely in all directions.
3. **Add gravity UI control**: Gravity is currently a Rust constant (`GRAVITY_STRENGTH`). Need to expose to JS and add slider.

The required changes are modifications to existing code, not new infrastructure.

## Detailed Findings

### Current Compute Shader Implementation

**File:** `/Users/kubanemil/codes/physicall/shaders/particle_compute.wgsl`

The existing compute shader implements N-body gravitational simulation:

```wgsl
// Lines 22-53: Current physics implementation
@compute @workgroup_size(256)
fn main(@builtin(global_invocation_id) id: vec3u) {
    let idx = id.x;
    if (idx >= params.particle_count) { return; }

    var particle = particles_in[idx];
    var acceleration = vec3f(0.0);

    // N-body: sum gravitational forces from ALL other particles
    for (var i = 0u; i < params.particle_count; i++) {
        if (i == idx) { continue; }
        let other = particles_in[i];
        let diff = other.position - particle.position;
        let dist_sq = dot(diff, diff) + 0.001; // Softening
        let dist = sqrt(dist_sq);
        let force_mag = params.gravity_strength / dist_sq;
        acceleration += (diff / dist) * force_mag;
    }

    // Semi-implicit Euler integration
    particle.velocity += acceleration * params.delta_time;
    particle.velocity *= params.damping;
    particle.position += particle.velocity * params.delta_time;

    particles_out[idx] = particle;
}
```

**Observation:** The N-body loop is O(n²) - each particle calculates force from all 10,000 other particles. For E2.2's constant gravity, this loop can be replaced with a single `acceleration = vec3f(0.0, -gravity, 0.0)`, making the shader O(n).

## Implementation Guidance

### Changes Required for E2.2

1. **Modify compute shader** (`particle_compute.wgsl`):
   - Remove N-body loop (O(n²) → O(n))
   - Add constant downward gravity: `acceleration = vec3f(0.0, -params.gravity_strength, 0.0)`
   - Add floor collision check: `if (particle.position.y < floor_y) { bounce }`

2. **Adjust gravity constant** (`lib.rs`):
   - Change from 0.00005 (N-body scale) to ~10.0 (Earth-like)
   - Make it mutable in State struct

3. **Add WASM binding** (`lib.rs`):
   - Add `set_gravity(strength: f32)` function with `#[wasm_bindgen]`
   - Store gravity in State, include in SimParams each frame

4. **Modify initial distribution** (`lib.rs`):
   - Spawn particles above floor (e.g., y > 0.5)
   - Could use box distribution instead of sphere

5. **Add UI** (`web/`):
   - Add HTML slider in `index.html`
   - Add JS event handler in `main.ts`
   - Import and call `set_gravity` from WASM

### Suggested SimParams Extension

Consider adding floor_y to SimParams for shader access:
```rust
struct SimParams {
    delta_time: f32,
    gravity_strength: f32,
    damping: f32,
    particle_count: u32,
    floor_y: f32,           // NEW: floor boundary
    bounce_damping: f32,    // NEW: energy loss on bounce
    _padding: [f32; 2],     // Align to 32 bytes
}
```
