# Research: E1.2 Primitive Rendering

## Research Question

How to implement primitive rendering (points, lines, spheres) in wgpu/WebGPU for the Physicall physics simulation framework, building on the existing camera system and triangle rendering infrastructure.

## Summary

The current codebase has a functional WebGPU renderer with an orbit camera, rendering a single triangle with vertex colors. To add primitive rendering support, the key findings are:

1. **Points**: WebGPU does NOT support variable point sizes via `@builtin(point_size)`. Points are always 1 pixel. The solution is to render instanced quads (billboards) with fragment shader discard for circular appearance.

2. **Lines**: WebGPU only supports 1-pixel wide lines via `LineList`/`LineStrip` topology. This is sufficient for debug visualization. Thicker lines require geometry expansion (quads).

3. **Spheres**: Icospheres are preferred over UV spheres for uniform vertex distribution. The `icosphere` Rust crate provides ready-to-use generation. For unit spheres, normals equal vertex positions.

4. **Instancing**: wgpu supports `VertexStepMode::Instance` for efficient rendering of many objects. Instance buffers provide per-instance transforms/properties while reusing geometry.

### Point Rendering

**Critical Finding: No Native Point Size Support**

WebGPU/WGSL does NOT support `@builtin(point_size)`. This was deliberately excluded from the spec due to:
- Inconsistent cross-platform behavior
- No HLSL equivalent
- Different APIs define point clipping differently

**Available Options:**

| Approach | Pros | Cons |
|----------|------|------|
| `PrimitiveTopology::PointList` | Simple, 1 draw call | Always 1 pixel, not visible |
| Instanced quads | Variable size, circular | More complex, 6 vertices/point |
| Billboarded sprites | Full control, textures | Most complex setup |

**Recommended Approach: Instanced Quads**

```wgsl
// Vertex shader for point rendering
struct PointInstance {
    @location(5) position: vec3f,
    @location(6) size: f32,
    @location(7) color: vec3f,
}

@vertex
fn vs_point(
    @location(0) quad_pos: vec2f,  // -1..1 quad corner
    instance: PointInstance,
) -> VertexOutput {
    // Scale and translate quad by instance data
    let world_pos = vec3f(
        quad_pos.x * instance.size + instance.position.x,
        quad_pos.y * instance.size + instance.position.y,
        instance.position.z,
    );
    out.clip_position = camera.view_proj * vec4f(world_pos, 1.0);
    out.uv = quad_pos * 0.5 + 0.5;
    return out;
}

// Fragment shader for circular points
@fragment
fn fs_point(in: VertexOutput) -> @location(0) vec4f {
    let dist = length(in.uv - vec2f(0.5));
    if (dist > 0.5) { discard; }
    return vec4f(in.color, 1.0);
}
```

**Quad Vertices (6 per point, or 4 with index buffer):**
```
(-1, -1), (1, -1), (-1, 1),  // Triangle 1
(-1,  1), (1, -1), ( 1, 1)   // Triangle 2
```

### Line Rendering

**WebGPU Line Width: Always 1 Pixel**

This is a deliberate spec decision for cross-platform consistency. For debug visualization, this is acceptable.

**Topology Options:**

| Topology | Usage | Index Format |
|----------|-------|--------------|
| `LineList` | Isolated segments (grid, bounds) | Not required |
| `LineStrip` | Connected paths (polylines) | Required if indexed |

**Pipeline Configuration for Lines:**
```rust
primitive: wgpu::PrimitiveState {
    topology: wgpu::PrimitiveTopology::LineList,
    strip_index_format: None,  // Set to Some(Uint16/32) for LineStrip
    cull_mode: None,  // Lines don't have faces
    ..Default::default()
}
```

**Line Vertex Format:**
Same as current `Vertex` struct (position + color). Each pair of vertices forms one line.

**Primitive Restart for LineStrip:**
- uint16: `0xFFFF`
- uint32: `0xFFFFFFFF`

Allows multiple disconnected strips in one draw call.

### Sphere Rendering (Icosphere)

**Icosphere vs UV Sphere:**

| Aspect | Icosphere | UV Sphere |
|--------|-----------|-----------|
| Vertex distribution | Uniform | Bunched at poles |
| Triangle quality | Consistent | Slivers at poles |
| UV mapping | Complex | Simple |
| Polygonal efficiency | Higher | Lower |

**Icosphere Generation Algorithm:**

1. Start with base icosahedron (12 vertices, 20 triangles)
2. For each subdivision level:
   - Split each triangle into 4 triangles
   - Place midpoints on unit sphere (normalize)
   - Use edge cache to prevent duplicate vertices

**Vertex/Triangle Counts:**

| Level | Vertices | Triangles |
|-------|----------|-----------|
| 0 | 12 | 20 |
| 1 | 42 | 80 |
| 2 | 162 | 320 |
| 3 | 642 | 1,280 |
| 4 | 2,562 | 5,120 |

Formula: `Vertices = 10 × 4^n + 2`, `Triangles = 20 × 4^n`

**Rust Crate Option:**
```toml
[dependencies]
icosphere = "0.1"
```

```rust
use icosphere::Icosphere;
let ico = Icosphere::new(3, |vertex| {
    Vertex {
        position: vertex.into(),
        normal: vertex.normalize().into(),
    }
});
```

**Normals for Unit Sphere:**
For smooth shading on a unit sphere at origin, `normal = normalize(position)`. This is a special property of spheres.

### Instanced Rendering

The codebase will need instancing for efficient sphere and point rendering.

**Buffer Layout Pattern:**

```rust
// Geometry buffer (per-vertex)
struct Vertex {
    position: [f32; 3],
    normal: [f32; 3],  // For spheres
}

impl Vertex {
    fn desc() -> VertexBufferLayout<'static> {
        VertexBufferLayout {
            array_stride: size_of::<Vertex>() as BufferAddress,
            step_mode: VertexStepMode::Vertex,  // Per vertex
            attributes: &[...],
        }
    }
}

// Instance buffer (per-instance)
struct Instance {
    model_matrix: [[f32; 4]; 4],  // Or just position + scale
}

impl Instance {
    fn desc() -> VertexBufferLayout<'static> {
        VertexBufferLayout {
            array_stride: size_of::<Instance>() as BufferAddress,
            step_mode: VertexStepMode::Instance,  // Per instance
            attributes: &[...],  // locations 5-8 for mat4
        }
    }
}
```

**Pipeline with Both Buffers:**
```rust
vertex: VertexState {
    buffers: &[Vertex::desc(), Instance::desc()],
    ...
}
```

**Draw Call:**
```rust
render_pass.set_vertex_buffer(0, vertex_buffer.slice(..));
render_pass.set_vertex_buffer(1, instance_buffer.slice(..));
render_pass.set_index_buffer(index_buffer.slice(..), IndexFormat::Uint32);
render_pass.draw_indexed(0..index_count, 0, 0..instance_count);
```

### Depth Buffer Requirement

Current renderer has no depth buffer. For spheres and 3D primitives, depth testing is required:

```rust
// Create depth texture
let depth_texture = device.create_texture(&TextureDescriptor {
    size: Extent3d { width, height, depth_or_array_layers: 1 },
    format: TextureFormat::Depth32Float,
    usage: TextureUsages::RENDER_ATTACHMENT,
    ...
});

// Pipeline depth stencil state
depth_stencil: Some(DepthStencilState {
    format: TextureFormat::Depth32Float,
    depth_write_enabled: true,
    depth_compare: CompareFunction::Less,
    stencil: StencilState::default(),
    bias: DepthBiasState::default(),
}),

// Render pass attachment
depth_stencil_attachment: Some(RenderPassDepthStencilAttachment {
    view: &depth_texture_view,
    depth_ops: Some(Operations {
        load: LoadOp::Clear(1.0),
        store: StoreOp::Store,
    }),
    stencil_ops: None,
}),
```

## Architecture Notes

**Proposed Module Structure:**

```
crates/physicall-core/src/
├── lib.rs                 # WASM exports, State orchestration
├── renderer/
│   ├── mod.rs            # Renderer trait, common types
│   ├── pipeline.rs       # Pipeline builders for each primitive type
│   ├── camera.rs         # OrbitCamera, Projection (move from lib.rs)
│   └── depth.rs          # Depth texture management
├── primitives/
│   ├── mod.rs
│   ├── point.rs          # Point/particle rendering (instanced quads)
│   ├── line.rs           # Line rendering (LineList pipeline)
│   └── sphere.rs         # Sphere rendering (icosphere + instancing)
└── mesh/
    └── icosphere.rs      # Icosphere generation (or use crate)
```

**Pipeline Strategy:**

1. **Point Pipeline**: TriangleList with instanced quads, fragment discard
2. **Line Pipeline**: LineList with same vertex format, no culling
3. **Sphere Pipeline**: TriangleList with icosphere mesh, instancing, depth buffer

All pipelines share the same camera bind group layout (group 0).

## Open Questions

1. **Depth buffer recreation on resize**: Need to recreate depth texture when window resizes. Current `resize()` method only reconfigures surface.

2. **Uniform color vs per-instance color**: PR FAQ defers per-instance colors to M2. Should points/lines/spheres have a single color uniform, or prepare for per-instance colors now?

3. **Sphere LOD**: Should sphere detail level be configurable, or fixed at a reasonable default (e.g., subdivision level 3)?

4. **Point billboard alignment**: Should points always face camera (world-space billboarding) or be aligned to world axes (simpler)?

5. **Multiple pipelines in single render pass**: All primitive types can render in the same pass by switching pipelines. Is this the preferred approach, or separate passes per type?
