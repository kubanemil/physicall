# Research: E3.3 Performance Display

## Research Question

Analyze the current render loop, frame timing, particle count system, and UI architecture to understand how to implement a real-time performance stats overlay (FPS, frame time, particle count) for the Physicall WebGPU simulation.

## Summary

The Physicall codebase already has all the raw data needed for a performance display. The TypeScript render loop (`web/src/main.ts:175-196`) drives frames via `requestAnimationFrame`, providing implicit frame-to-frame timing. The WASM layer already exports `get_particle_count()` (`crates/physicall-core/src/lib.rs:2149-2154`) which returns `active_particle_count` from the State struct. The existing particle count display in the controls panel (`web/index.html:23-25`) updates every 10 frames via a counter in the render loop (`web/src/main.ts:189-193`).

The UI follows a fixed-position HTML overlay pattern established by the controls panel (`web/src/style.css:52-64`). The controls panel lives at top-left; the PRFAQ specifies the stats panel at top-right. All UI is plain HTML/CSS with no framework — event handlers are wired up in `setupUIControls()` (`web/src/main.ts:130-169`). The existing keyboard handler pattern (`web/src/main.ts:225-229`) provides a model for the `Ctrl+Y` toggle shortcut.

## Detailed Findings

### Render Loop & Frame Timing

**TypeScript Render Loop** (`web/src/main.ts:175-196`)

```typescript
function renderLoop(): void {
  // Apply pending resize before rendering
  if (pendingWidth !== null && pendingHeight !== null) {
    if (pendingWidth > 0 && pendingHeight > 0) {
      canvas.width = pendingWidth;
      canvas.height = pendingHeight;
      resize(pendingWidth, pendingHeight);
    }
    pendingWidth = null;
    pendingHeight = null;
  }

  render();

  // Update particle count display every 10 frames for performance
  frameCount++;
  if (frameCount % 10 === 0 && particleCountDisplay) {
    particleCountDisplay.textContent = String(get_particle_count());
  }

  requestAnimationFrame(renderLoop);
}
```

Key observations:
- `requestAnimationFrame` provides a `DOMHighResTimeStamp` callback parameter, but it is **not currently used** — the function signature is `renderLoop(): void` with no timestamp parameter.
- Frame timing exists in the **WASM side** via `performance.now()` (`crates/physicall-core/src/lib.rs:1701-1712`), but this is not exposed to TypeScript.
- The `frameCount` variable (`web/src/main.ts:173`) already tracks frame numbers for throttling particle count updates.

**WASM-Side Frame Timing** (`crates/physicall-core/src/lib.rs:1700-1712`)

```rust
let now = web_sys::window()
    .expect("No window")
    .performance()
    .expect("No performance")
    .now();
let dt = match self.last_frame_time {
    Some(last) => ((now - last) / 1000.0) as f32,
    None => 1.0 / 60.0,
};
self.last_frame_time = Some(now);
let dt = dt.min(1.0 / 30.0);
```

This computes delta time in the Rust `render()` method for physics simulation. FPS can be derived from `1000 / frameTime` purely in TypeScript without needing this WASM-side data.

### Particle Count Access

**WASM Export** (`crates/physicall-core/src/lib.rs:2148-2154`)

```rust
#[wasm_bindgen]
pub fn get_particle_count() -> u32 {
    STATE.with(|s| {
        let state_ref = s.borrow();
        state_ref.as_ref().map(|state| state.active_particle_count).unwrap_or(0)
    })
}
```

## Architecture Notes

### FPS Calculation Approach

FPS will be calculated entirely in TypeScript using `requestAnimationFrame` timestamps:

```
requestAnimationFrame(callback) → callback receives DOMHighResTimeStamp
frameTime = currentTimestamp - lastTimestamp
fps = 1000 / frameTime (instantaneous)
smoothedFps = ema(fps, alpha=0.1) (smoothed)
```

No WASM changes needed. The `renderLoop` function signature will gain a `timestamp: DOMHighResTimeStamp` parameter from `requestAnimationFrame`.

### Display Update Throttling

Per the PRFAQ, stats values refresh every 500ms. Internal tracking runs every frame, but DOM updates are throttled:

```
Track: every frame → accumulate frameTime, increment framesSinceLastUpdate
Display: every 500ms → update DOM text nodes with averaged values
```
