# Research: E2.3 N-Body Simulation

## Research Question

How should the N-Body gravitational simulation be implemented in Physicall? Specifically:
1. N-body force calculation in the compute shader (particles attract each other)
2. Click-to-spawn interaction (mouse-to-world coordinate conversion)
3. Integration method for gravitational simulation
4. Input differentiation (camera orbit vs particle spawn)

## Summary

**Current State:** The codebase has E2.2 implemented - constant downward gravity with floor collision and 10,000 particles rendered via instanced quads. The compute shader uses semi-implicit Euler integration.

**Required Changes for E2.3:**
1. **Modify compute shader** to add O(n²) N-body gravitational attraction loop
2. **Add mass to Particle struct** (currently only has position, velocity, size)
3. **Add click-to-spawn** requiring:
   - Mouse event handler for click (distinct from drag)
   - Screen-to-world ray unprojection
   - WASM binding to add particles dynamically
   - Buffer management for growing particle count
4. **Tune physics parameters** (gravitational constant, softening factor, integration timestep)

**Key Decisions Needed:**
- Click vs drag differentiation: Suggest threshold-based (click = mousedown+mouseup without significant movement)
- Buffer strategy: Pre-allocate max capacity (simpler than dynamic resize)
- Integration method: Semi-implicit Euler is adequate; Verlet improves energy conservation

## Detailed Findings

### Current Physics Implementation

**File:** `shaders/particle_compute.wgsl`

The current compute shader implements constant downward gravity with floor collision:

```wgsl
// Lines 33-51: Current implementation (E2.2)
@compute @workgroup_size(256)
fn main(@builtin(global_invocation_id) id: vec3u) {
    let idx = id.x;
    if (idx >= params.particle_count) { return; }

    var particle = particles_in[idx];

    // Constant downward gravity (NOT N-body)
    let acceleration = vec3f(0.0, -params.gravity_strength, 0.0);

    // Semi-implicit Euler integration
    particle.velocity += acceleration * params.delta_time;
    particle.velocity *= params.damping;
    particle.position += particle.velocity * params.delta_time;

    // Floor collision
    if (particle.position.y < params.floor_y) {
        particle.position.y = params.floor_y;
        if (particle.velocity.y < 0.0) {
            particle.velocity.y = -particle.velocity.y * params.bounce_damping;
        }
    }

    particles_out[idx] = particle;
}
```

**Observation:** No particle-to-particle forces exist. Each particle only experiences constant downward acceleration.

**Observation:** Current implementation treats all left-click-drag as camera rotation. To differentiate click (spawn) from drag (camera):

1. **Threshold approach:** Track movement distance. If mouseup occurs within N pixels of mousedown AND within M milliseconds, treat as click.
2. **Button approach:** Left-click spawns, right-click-drag orbits (cleanest separation).
3. **Modifier approach:** Shift+click spawns (more discoverable).

**Recommendation:** Threshold approach is most natural - small movements spawn, larger drags orbit.

**Current initialization (lib.rs:1000-1021):**
- Buffers created with exact size for PARTICLE_COUNT
- Usage: `STORAGE | VERTEX | COPY_DST`

**For dynamic spawning, two approaches:**

1. **Pre-allocate max capacity:**
   - Create buffers with MAX_PARTICLES (e.g., 20,000)
   - Track `active_particle_count` separately
   - Compute shader only processes active particles
   - New particles written via `queue.write_buffer()`
   - **Pros:** Simple, no reallocation
   - **Cons:** Memory overhead

2. **Dynamic resize:**
   - Create new larger buffers when full
   - Copy existing data
   - Recreate bind groups
   - **Pros:** Memory efficient
   - **Cons:** Complex, causes frame hitch

**Recommendation:** Pre-allocate with MAX_PARTICLES = 10,000 (enough for demo, ~320KB per buffer).

### Integration Methods

**Current:** Semi-implicit Euler (velocity-first)
```wgsl
velocity += acceleration * dt;
position += velocity * dt;
```

**Verlet (better energy conservation):**
```wgsl
// Requires storing previous position or using velocity Verlet
// Velocity Verlet:
let half_accel = acceleration * 0.5 * dt;
velocity += half_accel;
position += velocity * dt;
// (recompute acceleration with new positions)
velocity += half_accel;
```

**For N-body simulation:**
- Semi-implicit Euler is adequate for visual demo
- Verlet provides better long-term stability for orbits
- RK4 is overkill for this use case

**Recommendation:** Keep semi-implicit Euler for simplicity. Can upgrade to Verlet if orbits decay noticeably.

### N-Body Algorithm

**Basic O(n²) approach:**
```wgsl
var acceleration = vec3f(0.0);
for (var i = 0u; i < particle_count; i++) {
    if (i == idx) { continue; }
    let other = particles_in[i];
    let diff = other.position - particle.position;
    let dist_sq = dot(diff, diff) + softening_sq;  // Prevent singularity
    let dist = sqrt(dist_sq);
    let force_mag = G / dist_sq;  // Assumes unit mass
    acceleration += (diff / dist) * force_mag;
}
```

**Performance considerations:**
- 10,000 particles = 100M force calculations per frame
- Each workgroup of 256 threads reads all particles
- GPU memory bandwidth limited
- Acceptable for demo; not scalable beyond ~2000 for smooth 60fps

**Optimizations (out of scope for E2.3):**
- Spatial hashing / Barnes-Hut (M4)
- Shared memory tiling in compute shader
- Reduce particle count for N-body demo

### N-Body Compute Shader Structure

```wgsl
struct Particle {
    position: vec3f,
    size: f32,
    velocity: vec3f,
    _padding: f32,
}

struct SimParams {
    delta_time: f32,
    gravitational_constant: f32,  // G
    damping: f32,
    particle_count: u32,
    softening_sq: f32,            // epsilon²
    // ... additional params
}

@compute @workgroup_size(256)
fn main(@builtin(global_invocation_id) id: vec3u) {
    let idx = id.x;
    if (idx >= params.particle_count) { return; }

    var particle = particles_in[idx];
    var acceleration = vec3f(0.0);

    // N-body force accumulation
    for (var i = 0u; i < params.particle_count; i++) {
        if (i == idx) { continue; }
        let other = particles_in[i];
        let diff = other.position - particle.position;
        let dist_sq = dot(diff, diff) + params.softening_sq;
        let dist = sqrt(dist_sq);
        let force_mag = params.gravitational_constant / dist_sq;
        acceleration += (diff / dist) * force_mag;
    }

    // Integration (semi-implicit Euler)
    particle.velocity += acceleration * params.delta_time;
    particle.velocity *= params.damping;
    particle.position += particle.velocity * params.delta_time;

    particles_out[idx] = particle;
}
```

### Ray Unprojection Algorithm

```rust
fn screen_to_world_ray(
    screen_x: f32,      // 0 to canvas_width
    screen_y: f32,      // 0 to canvas_height
    width: u32,
    height: u32,
    camera: &OrbitCamera,
    projection: &Projection,
) -> (Vec3, Vec3) {  // Returns (origin, direction)
    // 1. Convert to NDC (-1 to 1)
    let ndc_x = (2.0 * screen_x / width as f32) - 1.0;
    let ndc_y = 1.0 - (2.0 * screen_y / height as f32);  // Y flipped

    // 2. Get inverse view-projection
    let view = camera.view_matrix();
    let proj = projection.matrix();
    let inv_view_proj = (proj * view).inverse();

    // 3. Unproject near and far points
    let near_ndc = Vec4::new(ndc_x, ndc_y, 0.0, 1.0);
    let far_ndc = Vec4::new(ndc_x, ndc_y, 1.0, 1.0);

    let near_world = inv_view_proj * near_ndc;
    let far_world = inv_view_proj * far_ndc;

    let near_world = near_world.truncate() / near_world.w;
    let far_world = far_world.truncate() / far_world.w;

    // 4. Ray from near to far
    let direction = (far_world - near_world).normalize();

    (near_world, direction)
}

fn ray_plane_intersection(
    ray_origin: Vec3,
    ray_dir: Vec3,
    plane_point: Vec3,    // e.g., camera.target
    plane_normal: Vec3,   // e.g., Vec3::Y for horizontal plane
) -> Option<Vec3> {
    let denom = ray_dir.dot(plane_normal);
    if denom.abs() < 0.0001 { return None; }  // Ray parallel to plane

    let t = (plane_point - ray_origin).dot(plane_normal) / denom;
    if t < 0.0 { return None; }  // Intersection behind ray

    Some(ray_origin + ray_dir * t)
}
```
