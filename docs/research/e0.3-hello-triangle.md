# Research: E0.3 Hello Triangle

## Research Question

How to implement a basic "Hello Triangle" in wgpu for the Physicall project? This involves creating a render pipeline, writing WGSL shaders, and rendering a colored triangle on the existing WebGPU canvas.

## Summary

E0.3 builds on the existing WebGPU initialization (E0.2) to render a triangle. The implementation requires three main components: (1) a WGSL shader file with vertex and fragment stages, (2) a render pipeline that connects the shader to the GPU, and (3) vertex data defining the triangle's positions and colors.

The current codebase already has WebGPU fully initialized with surface configuration and a render loop. The `State` struct in `lib.rs` needs to be extended with a `RenderPipeline` and a `VertexBuffer`. The render pass currently clears to a solid color - this needs to be modified to also draw the triangle.

Key implementation decisions:
- **Shader loading**: Use `include_str!()` for compile-time embedding (best for WASM)
- **Vertex format**: Position (vec3f) + Color (vec3f) = 24 bytes per vertex
- **Triangle winding**: Counter-clockwise (CCW) for front-facing
- **Shader location**: Create `shaders/` directory at project root per PROJECT_PLAN.md

### 2. Required Dependencies

Add to `crates/physicall-core/Cargo.toml`:

```toml
[dependencies]
bytemuck = { version = "1.21", features = ["derive"] }
```

The `bytemuck` crate is required to safely cast Rust structs to byte slices for GPU buffers. The `derive` feature enables `#[derive(Pod, Zeroable)]` macros.

### 3. Vertex Data Structure

Define a vertex struct with position and color:

```rust
use bytemuck::{Pod, Zeroable};

#[repr(C)]
#[derive(Copy, Clone, Debug, Pod, Zeroable)]
pub struct Vertex {
    position: [f32; 3],  // 12 bytes @ offset 0
    color: [f32; 3],     // 12 bytes @ offset 12
}                        // Total: 24 bytes per vertex

impl Vertex {
    const ATTRIBS: [wgpu::VertexAttribute; 2] = wgpu::vertex_attr_array![
        0 => Float32x3,  // position @ location(0)
        1 => Float32x3,  // color @ location(1)
    ];

    pub fn desc() -> wgpu::VertexBufferLayout<'static> {
        wgpu::VertexBufferLayout {
            array_stride: std::mem::size_of::<Vertex>() as wgpu::BufferAddress,
            step_mode: wgpu::VertexStepMode::Vertex,
            attributes: &Self::ATTRIBS,
        }
    }
}
```

Triangle vertex data (in normalized device coordinates, -1 to 1):

```rust
const VERTICES: &[Vertex] = &[
    Vertex { position: [0.0, 0.5, 0.0], color: [1.0, 0.0, 0.0] },    // Top (red)
    Vertex { position: [-0.5, -0.5, 0.0], color: [0.0, 1.0, 0.0] },  // Bottom-left (green)
    Vertex { position: [0.5, -0.5, 0.0], color: [0.0, 0.0, 1.0] },   // Bottom-right (blue)
];
```

### 4. WGSL Shader

Create `shaders/triangle.wgsl`:

```wgsl
// Vertex input - matches VertexBufferLayout
struct VertexInput {
    @location(0) position: vec3f,
    @location(1) color: vec3f,
}

// Vertex output - data passed to fragment shader
struct VertexOutput {
    @builtin(position) clip_position: vec4f,
    @location(0) color: vec3f,
}

@vertex
fn vs_main(input: VertexInput) -> VertexOutput {
    var output: VertexOutput;
    output.clip_position = vec4f(input.position, 1.0);
    output.color = input.color;
    return output;
}

@fragment
fn fs_main(input: VertexOutput) -> @location(0) vec4f {
    return vec4f(input.color, 1.0);
}
```

Key WGSL concepts:
- `@location(n)` maps to `shader_location` in Rust's `VertexAttribute`
- `@builtin(position)` is required output for clip-space position
- Fragment output `@location(0)` targets the first color attachment
- GPU automatically interpolates colors across the triangle surface

### 5. Shader Loading Strategy

For WASM targets, use compile-time embedding:

```rust
let shader = device.create_shader_module(wgpu::ShaderModuleDescriptor {
    label: Some("Triangle Shader"),
    source: wgpu::ShaderSource::Wgsl(
        include_str!("../../../shaders/triangle.wgsl").into()
    ),
});
```

Path rationale: From `crates/physicall-core/src/lib.rs`, go up three levels to project root, then into `shaders/`.

Alternative using `include_wgsl!` macro (if available in wgpu version):
```rust
let shader = device.create_shader_module(wgpu::include_wgsl!("../../../shaders/triangle.wgsl"));
```

### 6. Render Pipeline Creation

Add to `State::new()` after surface configuration:

```rust
// Load shader
let shader = device.create_shader_module(wgpu::ShaderModuleDescriptor {
    label: Some("Triangle Shader"),
    source: wgpu::ShaderSource::Wgsl(
        include_str!("../../../shaders/triangle.wgsl").into()
    ),
});

// Create render pipeline
let render_pipeline = device.create_render_pipeline(&wgpu::RenderPipelineDescriptor {
    label: Some("Render Pipeline"),
    layout: None,  // Auto-layout for simple pipelines
    vertex: wgpu::VertexState {
        module: &shader,
        entry_point: Some("vs_main"),
        buffers: &[Vertex::desc()],
        compilation_options: wgpu::PipelineCompilationOptions::default(),
    },
    fragment: Some(wgpu::FragmentState {
        module: &shader,
        entry_point: Some("fs_main"),
        targets: &[Some(wgpu::ColorTargetState {
            format: surface_format,
            blend: Some(wgpu::BlendState::REPLACE),
            write_mask: wgpu::ColorWrites::ALL,
        })],
        compilation_options: wgpu::PipelineCompilationOptions::default(),
    }),
    primitive: wgpu::PrimitiveState {
        topology: wgpu::PrimitiveTopology::TriangleList,
        strip_index_format: None,
        front_face: wgpu::FrontFace::Ccw,
        cull_mode: Some(wgpu::Face::Back),
        polygon_mode: wgpu::PolygonMode::Fill,
        unclipped_depth: false,
        conservative: false,
    },
    depth_stencil: None,
    multisample: wgpu::MultisampleState {
        count: 1,
        mask: !0,
        alpha_to_coverage_enabled: false,
    },
    multiview: None,
    cache: None,
});
```

### 8. Modified Render Function

Update `State::render()` to draw the triangle:

```rust
fn render(&self) -> Result<(), wgpu::SurfaceError> {
    let output = self.surface.get_current_texture()?;
    let view = output.texture.create_view(&wgpu::TextureViewDescriptor::default());

    let mut encoder = self.device.create_command_encoder(&wgpu::CommandEncoderDescriptor {
        label: Some("Render Encoder"),
    });

    {
        let mut render_pass = encoder.begin_render_pass(&wgpu::RenderPassDescriptor {
            label: Some("Render Pass"),
            color_attachments: &[Some(wgpu::RenderPassColorAttachment {
                view: &view,
                resolve_target: None,
                ops: wgpu::Operations {
                    load: wgpu::LoadOp::Clear(wgpu::Color {
                        r: 0.1,
                        g: 0.2,
                        b: 0.3,
                        a: 1.0,
                    }),
                    store: wgpu::StoreOp::Store,
                },
            })],
            depth_stencil_attachment: None,
            timestamp_writes: None,
            occlusion_query_set: None,
        });

        // Draw triangle
        render_pass.set_pipeline(&self.render_pipeline);
        render_pass.set_vertex_buffer(0, self.vertex_buffer.slice(..));
        render_pass.draw(0..3, 0..1);  // 3 vertices, 1 instance
    }

    self.queue.submit(std::iter::once(encoder.finish()));
    output.present();

    Ok(())
}
```

## Architecture Notes

The data flow for rendering a triangle:

```
1. Rust Code (lib.rs)
   └── Vertex struct with position + color
       └── VertexBufferLayout describes memory layout
           └── shader_location(0) = position
           └── shader_location(1) = color

2. WGSL Shader (triangle.wgsl)
   └── VertexInput reads @location(0) and @location(1)
       └── vs_main transforms to clip space
           └── VertexOutput passes color to fragment
               └── fs_main outputs final RGBA color

3. Render Pipeline
   └── Connects shader to GPU state
       └── Vertex stage uses Vertex::desc() layout
           └── Fragment stage targets surface format
               └── Primitive state: TriangleList, CCW, Back-cull

4. Render Pass
   └── Clear to background color
       └── Set pipeline
           └── Bind vertex buffer to slot 0
               └── draw(0..3, 0..1) renders 3 vertices
```

## Open Questions

1. **Shader file location**: The PROJECT_PLAN.md specifies `shaders/render/` and `shaders/compute/` directories. For M0, a flat `shaders/triangle.wgsl` is simpler. Should we organize into subdirectories now or defer to M1?

2. **Multiview field**: The `RenderPipelineDescriptor` has a `multiview` field (for VR rendering). Current wgpu may use `multiview: None` or `multiview_mask: None`. Need to verify with wgpu 28.0 API.

3. **Entry point strings**: Recent wgpu versions use `entry_point: Some("vs_main")` vs older `entry_point: "vs_main"`. Verify exact API for wgpu 28.0.
