# Research: E0.1 Project Setup

## Research Question

How to set up a Rust + wasm-pack + Vite project for WebGPU-based physics simulations? What are the best practices for project structure, dependencies, and build configuration?

## Summary

Setting up a Rust WASM project with wgpu and Vite requires careful coordination of several tools. The recommended approach uses **wasm-pack with `--target web`** to generate ES modules, combined with **vite-plugin-wasm** for seamless Vite integration. The project should use a Cargo workspace structure with the WASM crate in a `crates/` directory.

Key findings:
1. **wgpu 28.0** is the current version with full WebGPU and WebGL2 support
2. **`--target web`** is preferred over `--target bundler` for modern browser workflows
3. **vite-plugin-wasm + vite-plugin-top-level-await** is the cleanest Vite integration
4. **console_error_panic_hook** is essential for debugging WASM panics
5. For WebGPU (not WebGL), builds require `RUSTFLAGS=--cfg=web_sys_unstable_apis`

## Detailed Findings

### 1. Cargo Configuration

#### Workspace Root (Cargo.toml)

```toml
[workspace]
resolver = "2"
members = ["crates/physicall-core"]

[workspace.package]
edition = "2021"
version = "0.1.0"

[workspace.dependencies]
wasm-bindgen = "0.2.100"
web-sys = "0.3.77"
js-sys = "0.3.77"
wasm-bindgen-futures = "0.4.43"
console_error_panic_hook = "0.1.7"
console_log = "1.0"
log = "0.4"
wgpu = "28.0"
```

#### WASM Crate (crates/physicall-core/Cargo.toml)

```toml
[package]
name = "physicall-core"
version.workspace = true
edition.workspace = true

[lib]
crate-type = ["cdylib", "rlib"]

[dependencies]
wasm-bindgen = { workspace = true }
console_error_panic_hook = { workspace = true }
log = { workspace = true }

# For console logging
[dependencies.web-sys]
workspace = true
features = ["console"]

[features]
default = ["console_error_panic_hook"]
```

**Why `cdylib` and `rlib`?**
- `cdylib`: Required for wasm-pack to produce a `.wasm` file
- `rlib`: Enables `wasm-pack test` for unit testing

### 2. wasm-pack Build Configuration

#### Recommended Command

```bash
wasm-pack build --target web --out-dir pkg
```

#### Target Options

| Target | Output | Use Case |
|--------|--------|----------|
| `--target web` | ES modules, no bundler needed | **Recommended for Vite** |
| `--target bundler` | CommonJS, requires bundler | Webpack workflows |
| `--target nodejs` | Node.js CommonJS | Server-side WASM |

#### WebGPU Unstable APIs

For WebGPU (not WebGL fallback), you must enable unstable web-sys APIs:

```bash
RUSTFLAGS=--cfg=web_sys_unstable_apis wasm-pack build --target web
```

### 3. Vite Configuration

#### Option A: vite-plugin-wasm (Recommended)

```typescript
// vite.config.ts
import { defineConfig } from 'vite';
import wasm from 'vite-plugin-wasm';
import topLevelAwait from 'vite-plugin-top-level-await';

export default defineConfig({
  plugins: [
    wasm(),
    topLevelAwait()
  ],
  // Exclude WASM package from dependency optimization
  optimizeDeps: {
    exclude: ['physicall-core']
  }
});
```

**Dependencies:**
```json
{
  "devDependencies": {
    "vite": "^6.0.0",
    "vite-plugin-wasm": "^3.4.1",
    "vite-plugin-top-level-await": "^1.4.4",
    "typescript": "^5.7.0"
  }
}
```

#### Option B: vite-plugin-wasm-pack (Auto-rebuild)

```typescript
// vite.config.ts
import { defineConfig } from 'vite';
import wasmPack from 'vite-plugin-wasm-pack';

export default defineConfig({
  plugins: [wasmPack('./crates/physicall-core')]
});
```

**Note:** This plugin only works with `--target web` builds.

### 4. Console Logging from Rust

#### Recommended Approach: Manual Binding with Macro

```rust
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
extern "C" {
    #[wasm_bindgen(js_namespace = console)]
    fn log(s: &str);
}

macro_rules! console_log {
    ($($t:tt)*) => (log(&format_args!($($t)*).to_string()))
}

#[wasm_bindgen(start)]
pub fn init() {
    // Set panic hook for better error messages
    #[cfg(feature = "console_error_panic_hook")]
    console_error_panic_hook::set_once();

    console_log!("WASM initialized!");
}
```

#### Alternative: Using console_log Crate

```rust
use log::info;

#[wasm_bindgen(start)]
pub fn init() {
    console_log::init_with_level(log::Level::Debug).expect("error initializing log");
    console_error_panic_hook::set_once();
    info!("WASM initialized!");
}
```

### 5. TypeScript WASM Loading

### 8. Version Compatibility Matrix

| Package | Version | Notes |
|---------|---------|-------|
| wgpu | 28.0 | Latest, WebGPU+WebGL2 support |
| wasm-bindgen | 0.2.100 | Must match wasm-bindgen-cli |
| wasm-bindgen-futures | 0.4.43 | For async/Promise bridging |
| web-sys | 0.3.77 | Web API bindings |
| console_error_panic_hook | 0.1.7 | Better panic messages |
| console_log | 1.0 | Rust log → browser console |
| vite | 6.0+ | Modern bundler |
| vite-plugin-wasm | 3.4.1 | WASM import support |
| vite-plugin-top-level-await | 1.4.4 | Top-level await support |

**Critical:** The `wasm-bindgen-cli` version (installed via `cargo install wasm-bindgen-cli`) must match the `wasm-bindgen` crate version in Cargo.toml.

## Architecture Notes

The architecture follows a clean separation:

1. **Rust/WASM layer** (`crates/physicall-core/`): Compiled to WASM, exports functions via `#[wasm_bindgen]`
2. **TypeScript layer** (`src/` or `web/src/`): Imports WASM module, handles UI
3. **Build pipeline**: wasm-pack generates `pkg/` with `.wasm` + `.js` + `.d.ts` files

Data flow:
```
TypeScript → import init() → WASM module initialized
TypeScript → call exported functions → Rust code executes
Rust → console_log!() → Browser console
```

## Open Questions

1. **Hot reload for Rust?** Currently requires manual rebuild. `vite-plugin-wasm-pack` may help but adds complexity.

2. **WebGPU vs WebGL for M0?** WebGL has broader support, but WebGPU is the learning goal. Decision: Start with WebGPU, add WebGL fallback in M1 if needed.

3. **Monorepo structure?** The PROJECT_PLAN.md shows a `web/` subdirectory. For simplicity in M0, consider putting TypeScript directly in root. Can restructure later.
