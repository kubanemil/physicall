# Research: E3.1 UI Controls

## Research Question

Analyze current WASM↔JS interop patterns and simulation state management to understand how to implement UI controls (pause/resume, reset, parameter sliders) for the Physicall WebGPU physics simulation.

## Summary

The Physicall codebase has a well-established WASM↔JS interop pattern using `wasm_bindgen` with thread-local state storage. Five functions are currently exported: `init()`, `init_webgpu()`, `render()`, `resize()`, and `reset_camera()`. The simulation uses a ping-pong double-buffered compute pattern with a `SimParams` uniform buffer that is updated every frame. This existing infrastructure provides a clear path for implementing UI controls: new WASM functions can be exported for pause/resume/reset, and parameter updates can follow the existing `queue.write_buffer()` pattern used for SimParams.

The key implementation decisions involve: (1) storing a paused flag in State to skip compute dispatch, (2) storing initial particle data for reset functionality, and (3) exposing setter functions for individual parameters that update the State fields used when constructing SimParams each frame.

### Animation Loop Implementation

**TypeScript Render Loop** (`web/src/main.ts:117-131`)
```typescript
function renderLoop(): void {
  // Apply pending resize before rendering
  if (pendingWidth !== null && pendingHeight !== null) {
    if (pendingWidth > 0 && pendingHeight > 0) {
      canvas.width = pendingWidth;
      canvas.height = pendingHeight;
      resize(pendingWidth, pendingHeight);
    }
    pendingWidth = null;
    pendingHeight = null;
  }

  render();
  requestAnimationFrame(renderLoop);
}
```

**Key Characteristic**: Continuous loop, calls WASM `render()` every frame.

### Implementation Strategy for UI Controls

**1. Pause/Resume**
- Add `paused: bool` field to `State` struct
- In `render()`, skip compute pass dispatch when paused
- Continue camera updates and render pass (user can orbit while paused)
- Export `set_paused(paused: bool)` WASM function

**2. Reset**
- Store `initial_particles: Vec<Particle>` in `State` during initialization
- Export `reset_simulation()` WASM function that:
  - Writes initial_particles to both particle buffers
  - Resets `active_particle_count` to initial value
  - Resets `frame_index` to 0

**3. Parameter Sliders**
- Add mutable fields to `State`: `gravity: f32`, `time_scale: f32`
- Export setter functions: `set_gravity(value: f32)`, `set_time_scale(value: f32)`
- Modify SimParams construction to use state fields instead of constants
- Updates take effect next frame automatically

**4. UI Implementation**
- Plain HTML elements in `index.html` (no framework needed)
- CSS styling in `style.css`
- JavaScript event listeners in `main.ts` calling WASM exports
