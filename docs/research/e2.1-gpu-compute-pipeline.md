# Research: E2.1 GPU Compute Pipeline

## Research Question

How is the GPU compute pipeline implemented in the Physicall codebase? What patterns are used for compute-render buffer sharing and double-buffering?

## Summary

**E2.1 is already fully implemented.** The codebase has a complete GPU compute pipeline with:

1. **Double-buffered particle storage** using a ping-pong pattern for safe read/write access
2. **N-body gravitational simulation** running in a compute shader with 10,000 particles
3. **Zero-copy buffer sharing** between compute and render stages via `STORAGE | VERTEX` buffer usage flags
4. **Semi-implicit Euler integration** with damping and softening for numerical stability

The implementation follows wgpu best practices for WebGPU compute pipelines. The compute shader reads from one buffer and writes to another, with the render pass reading from the just-written buffer. Frame timing uses actual delta time for consistent simulation speed.

## Detailed Findings

### Compute Pipeline Architecture

The compute pipeline is set up in `State::new()` with the following components:

**Bind Group Layout** (`crates/physicall-core/src/lib.rs:1036-1074`):
```
Binding 0: Storage buffer (read-only)  - Input particles
Binding 1: Storage buffer (read-write) - Output particles
Binding 2: Uniform buffer             - Simulation parameters
```

**Pipeline Creation** (`crates/physicall-core/src/lib.rs:1093-1100`):
- Uses `create_compute_pipeline()` with explicit layout
- Entry point: `main`
- Shader loaded via `include_str!()` from `shaders/particle_compute.wgsl`

### Double-Buffering (Ping-Pong Pattern)

**Buffer Setup** (`crates/physicall-core/src/lib.rs:1004-1020`):
- Two particle buffers created with identical content
- Usage flags: `STORAGE | VERTEX | COPY_DST`
- `STORAGE` enables compute shader access
- `VERTEX` enables render pipeline access as instance data
- `COPY_DST` allows initial data upload

**Bind Group Pairs** (`crates/physicall-core/src/lib.rs:1105-1142`):
- `compute_bind_groups[0]`: reads buffer[0], writes buffer[1]
- `compute_bind_groups[1]`: reads buffer[1], writes buffer[0]

**Frame Selection** (`crates/physicall-core/src/lib.rs:1323-1324`):
```rust
let read_idx = (self.frame_index % 2) as usize;
let write_idx = ((self.frame_index + 1) % 2) as usize;
```

### Compute Dispatch

**Per-Frame Execution** (`crates/physicall-core/src/lib.rs:1327-1337`):
1. Begin compute pass
2. Set compute pipeline
3. Set bind group based on current frame index
4. Dispatch workgroups: `ceil(particle_count / 256)`
5. End compute pass (implicit barrier before render)

**Workgroup Size**: 256 threads (hardcoded in shader, matches dispatch calculation)

### Compute Shader Details

**Location**: `shaders/particle_compute.wgsl`

**Data Structures** (lines 4-16):
```wgsl
struct Particle {
    position: vec3f,
    size: f32,
    velocity: vec3f,
    _padding: f32,  // Align to 32 bytes
}

struct SimParams {
    delta_time: f32,
    gravity_strength: f32,
    damping: f32,
    particle_count: u32,
}
```

**N-Body Algorithm** (lines 32-44):
- Iterates all particles (O(n^2) complexity)
- Applies gravitational force: `F = G * m / r^2`
- Softening factor of 0.001 prevents singularity at r=0

**Integration** (lines 46-52):
- Semi-implicit Euler: velocity updated first, then position
- Damping applied to velocity each frame (0.998)
- Delta time from simulation parameters

### Render Integration

**Instance Buffer Binding** (`crates/physicall-core/src/lib.rs:1377-1383`):
```rust
render_pass.set_vertex_buffer(1, self.particle_buffers[write_idx].slice(..));
```
- Render reads from the buffer just written by compute (`write_idx`)
- Point pipeline uses `Particle::desc()` for instance vertex layout

**Point Shader** (`shaders/point.wgsl:18-22`):
```wgsl
struct InstanceInput {
    @location(1) world_pos: vec3f,
    @location(2) size: f32,
    @location(3) velocity: vec3f,
}
```
- Matches `Particle` struct layout (minus padding)
- Velocity used for color mapping (blue=slow, red=fast)

### Simulation Parameters

**Constants** (`crates/physicall-core/src/lib.rs:442-446`):
```rust
const PARTICLE_COUNT: u32 = 10_000;
const PARTICLE_SIZE: f32 = 0.008;
const GRAVITY_STRENGTH: f32 = 0.00005;
const DAMPING: f32 = 0.998;
```

**Uniform Buffer Update** (`crates/physicall-core/src/lib.rs:1291-1301`):
- Updated every frame with actual delta time
- Delta time clamped to max 1/30s to prevent instability on lag spikes

### Initial Particle Distribution

**Golden Ratio Spiral** (`crates/physicall-core/src/lib.rs:448-491`):
- Particles distributed on a sphere using Fibonacci spiral
- Base radius: 3.0 units with slight variation
- Initial velocity: small tangential component for rotation

## Architecture Notes

### Data Flow Per Frame

```
┌─────────────────────────────────────────────────────────────────┐
│ Frame N (frame_index = 0)                                       │
├─────────────────────────────────────────────────────────────────┤
│ 1. Update sim_params_buffer with delta_time                     │
│ 2. Compute Pass:                                                │
│    - Bind group 0: read buffer[0], write buffer[1]              │
│    - Dispatch 40 workgroups (10000/256)                         │
│ 3. [Implicit barrier - wgpu handles synchronization]            │
│ 4. Render Pass:                                                 │
│    - Read from buffer[1] as vertex instance data                │
│ 5. Increment frame_index to 1                                   │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ Frame N+1 (frame_index = 1)                                     │
├─────────────────────────────────────────────────────────────────┤
│ 1. Update sim_params_buffer with delta_time                     │
│ 2. Compute Pass:                                                │
│    - Bind group 1: read buffer[1], write buffer[0]              │
│    - Dispatch 40 workgroups                                     │
│ 3. [Implicit barrier]                                           │
│ 4. Render Pass:                                                 │
│    - Read from buffer[0] as vertex instance data                │
│ 5. Increment frame_index to 0 (wrapping)                        │
└─────────────────────────────────────────────────────────────────┘
```

### Memory Layout

```
Particle (32 bytes, aligned):
┌────────────┬────────────┬────────────┬────────────┐
│ position.x │ position.y │ position.z │    size    │  (16 bytes)
├────────────┼────────────┼────────────┼────────────┤
│ velocity.x │ velocity.y │ velocity.z │  _padding  │  (16 bytes)
└────────────┴────────────┴────────────┴────────────┘
```

### Implicit Synchronization

wgpu handles memory barriers automatically:
- Compute writes complete before render pass begins
- No explicit `memoryBarrier()` or pipeline barriers needed
- Queue submission order guarantees execution order
