# Research: E0.2 WebGPU Initialization

## Research Question

How to implement WebGPU initialization for the Physicall project using wgpu compiled to WASM, including canvas setup, browser compatibility checks, and resize handling?

## Summary

WebGPU initialization with wgpu in WASM requires several coordinated components: a Rust library using wgpu with WebGPU backend features, async initialization of the graphics pipeline (instance, adapter, device, queue), surface creation from an HTML canvas element, and TypeScript/JavaScript code for WebGPU detection and resize handling. The current codebase has a minimal WASM setup (E0.1 completed) but no WebGPU integration yet. The web frontend directory structure does not exist and needs to be created.

Key technical requirements include:
1. Adding wgpu dependency with `webgpu` feature and web-sys features for canvas access
2. Building with `RUSTFLAGS=--cfg=web_sys_unstable_apis` for WebGPU APIs
3. Implementing async initialization pattern using `wasm_bindgen_futures::spawn_local`
4. Creating TypeScript/HTML that checks for WebGPU support before loading WASM

#### Surface Creation from Canvas

```rust
use wasm_bindgen::JsCast;
use web_sys::HtmlCanvasElement;

fn get_canvas(canvas_id: &str) -> HtmlCanvasElement {
    let window = web_sys::window().expect("no global window");
    let document = window.document().expect("no document");
    document
        .get_element_by_id(canvas_id)
        .expect("canvas not found")
        .dyn_into::<HtmlCanvasElement>()
        .expect("element is not a canvas")
}

let canvas = get_canvas("canvas");

    .expect("failed to create surface");
```

#### Full Async Initialization Sequence

```rust
use wasm_bindgen::prelude::*;
use wasm_bindgen_futures::spawn_local;

#[wasm_bindgen(start)]
pub fn main() {
    console_error_panic_hook::set_once();
    spawn_local(run());
}

async fn run() {
    let canvas = get_canvas("canvas");

    // 1. Create Instance
    let instance = wgpu::Instance::new(&wgpu::InstanceDescriptor {
        backends: wgpu::Backends::BROWSER_WEBGPU,
        ..Default::default()
    });

    // 2. Create Surface
    let surface = instance
        .create_surface(wgpu::SurfaceTarget::Canvas(canvas.clone()))
        .expect("Failed to create surface");

    // 3. Request Adapter
    let adapter = instance
        .request_adapter(&wgpu::RequestAdapterOptions {
            power_preference: wgpu::PowerPreference::default(),
            compatible_surface: Some(&surface),
            force_fallback_adapter: false,
        })
        .await
        .expect("Failed to find adapter");

    // 4. Request Device and Queue
    let (device, queue) = adapter
        .request_device(&wgpu::DeviceDescriptor::default(), None)
        .await
        .expect("Failed to create device");

    // 5. Configure Surface
    let surface_caps = surface.get_capabilities(&adapter);
    let surface_format = surface_caps
        .formats
        .iter()
        .find(|f| f.is_srgb())
        .copied()
        .unwrap_or(surface_caps.formats[0]);

    let config = wgpu::SurfaceConfiguration {
        usage: wgpu::TextureUsages::RENDER_ATTACHMENT,
        format: surface_format,
        width: canvas.width(),
        height: canvas.height(),
        present_mode: wgpu::PresentMode::Fifo,
        alpha_mode: surface_caps.alpha_modes[0],
        view_formats: vec![],
        desired_maximum_frame_latency: 2,
    };

    surface.configure(&device, &config);

    log::info!("WebGPU initialized successfully!");
}
```

#### Detection Pattern

```typescript
async function checkWebGPUSupport(): Promise<{
  supported: boolean;
  error?: string;
}> {
  // Check secure context (HTTPS or localhost)
  if (!window.isSecureContext) {
    return {
      supported: false,
      error: "WebGPU requires HTTPS or localhost"
    };
  }

  // Check navigator.gpu exists
  if (!navigator.gpu) {
    return {
      supported: false,
      error: "WebGPU is not supported in this browser"
    };
  }

  // Try to get adapter
  try {
    const adapter = await navigator.gpu.requestAdapter();
    if (!adapter) {
      return {
        supported: false,
        error: "No WebGPU adapter available"
      };
    }
    return { supported: true };
  } catch (e) {
    return {
      supported: false,
      error: `WebGPU error: ${e}`
    };
  }
}
```

#### User-Friendly Error Messages

```typescript
function getErrorMessage(userAgent: string): string {
  const ua = userAgent.toLowerCase();

  if (ua.includes('firefox')) {
    return "WebGPU requires Firefox 141+ on Windows or Firefox 145+ on macOS.";
  }
  if (ua.includes('safari')) {
    return "WebGPU requires Safari 26+ on macOS/iOS 26+.";
  }
  if (ua.includes('chrome')) {
    return "WebGPU requires Chrome 113+. Ensure 'Use graphics acceleration' is enabled.";
  }

  return "Your browser does not support WebGPU. Try Chrome 113+, Firefox 141+, or Safari 26+.";
}
```

### Canvas Resize Handling

#### ResizeObserver Pattern (TypeScript)

```typescript
const canvas = document.getElementById('canvas') as HTMLCanvasElement;

let pendingWidth: number | null = null;
let pendingHeight: number | null = null;

const observer = new ResizeObserver((entries) => {
  const entry = entries[0];

  // Use devicePixelContentBoxSize for HiDPI, with fallback
  const dpr = Math.min(2, window.devicePixelRatio);
  pendingWidth = Math.round(
    entry.devicePixelContentBoxSize?.[0].inlineSize ??
    entry.contentBoxSize[0].inlineSize * dpr
  );
  pendingHeight = Math.round(
    entry.devicePixelContentBoxSize?.[0].blockSize ??
    entry.contentBoxSize[0].blockSize * dpr
  );
});

try {
  observer.observe(canvas, { box: 'device-pixel-content-box' });
} catch {
  observer.observe(canvas, { box: 'content-box' });
}
```

#### Surface Reconfiguration (Rust)

```rust
pub fn resize(&mut self, new_width: u32, new_height: u32) {
    if new_width > 0 && new_height > 0 {
        self.config.width = new_width;
        self.config.height = new_height;
        self.surface.configure(&self.device, &self.config);
    }
}
```

#### Error Handling on Resize

```rust
match self.surface.get_current_texture() {
    Ok(output) => { /* render */ }
    Err(wgpu::SurfaceError::Lost | wgpu::SurfaceError::Outdated) => {

        self.surface.configure(&self.device, &self.config);
```

### Rendering a Solid Color (E0.2.1)

#### Basic Render Pass

```rust
pub fn render(&mut self) -> Result<(), wgpu::SurfaceError> {
    let output = self.surface.get_current_texture()?;
    let view = output.texture.create_view(&wgpu::TextureViewDescriptor::default());

    let mut encoder = self.device.create_command_encoder(
        &wgpu::CommandEncoderDescriptor { label: Some("Render Encoder") }
    );

    {
        let _render_pass = encoder.begin_render_pass(&wgpu::RenderPassDescriptor {
            label: Some("Render Pass"),
            color_attachments: &[Some(wgpu::RenderPassColorAttachment {
                view: &view,
                resolve_target: None,
                ops: wgpu::Operations {
                    load: wgpu::LoadOp::Clear(wgpu::Color {
                        r: 0.1,  // Dark blue-gray background
                        g: 0.2,
                        b: 0.3,
                        a: 1.0,
                    }),
                    store: wgpu::StoreOp::Store,
                },
            })],
            depth_stencil_attachment: None,
            timestamp_writes: None,
            occlusion_query_set: None,
        });
    }

    self.queue.submit(std::iter::once(encoder.finish()));
    output.present();

    Ok(())
}
```

## Architecture Notes

The WebGPU initialization flow:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                            Browser                                       │
├─────────────────────────────────────────────────────────────────────────┤
│  index.html                                                              │
│    └── Check navigator.gpu                                               │
│          ├── Not supported → Show error message (E0.2.2)                 │
│          └── Supported → Load WASM module                                │
│                              │                                           │
│  main.ts                     ▼                                           │
│    └── init() from WASM ────────────────────────────────────────────┐   │
│    └── ResizeObserver ─────────────────────────────────────────────┐│   │
│                                                                     ││   │
│  WASM Module (Rust)                                                 ││   │
│    ├── spawn_local(run()) ◄─────────────────────────────────────────┘│   │
│    │     ├── Instance::new(BROWSER_WEBGPU)                           │   │
│    │     ├── create_surface(Canvas)                                  │   │
│    │     ├── request_adapter() [async]                               │   │
│    │     ├── request_device() [async]                                │   │
│    │     └── surface.configure()                                     │   │
│    │                                                                 │   │
│    └── resize(width, height) ◄───────────────────────────────────────┘   │
│          └── surface.configure() with new dimensions                     │
└─────────────────────────────────────────────────────────────────────────┘
```

**State Management Options**:

1. **Thread-local static with RefCell** - Simple, works for single-threaded WASM
2. **Struct with exported methods** - More idiomatic, requires careful lifetime management
3. **Global mutable state with lazy_static** - Works but not recommended

Recommended approach for Physicall: Create a `State` struct that holds all wgpu resources, store it in thread-local storage, and expose `render()` and `resize()` functions.

## Open Questions

1. **Animation loop ownership**: Should the render loop be driven from JavaScript (requestAnimationFrame) or from Rust? JavaScript is simpler and more standard.

2. **State management**: How to safely store and access the wgpu State from exported functions? Thread-local `RefCell` is common but has ergonomic trade-offs.

3. **Error reporting to user**: How should Rust-side initialization errors be communicated back to the TypeScript UI? Options: return Result from async init, use custom error type, or log to console.

4. **Canvas sizing strategy**: Should the canvas fill the viewport or have fixed dimensions initially? Fill viewport is more interactive but requires immediate resize handling.
